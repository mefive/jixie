# 02 · 多策略组合层:从「跑一个策略」到「运转一组策略」

## 问题陈述

jixie 当前的世界观是「一个策略 = 一次回测 = 一份结果」。但个人投资系统的真实终态几乎必然是
**一个账户上并行运转 2~5 个低相关策略**:趋势 + 价值分红 + 微盘反转,各管一块钱、各按各的节奏调仓。
理由是老生常谈但成立的——单策略必有歇菜期(趋势策略在震荡市、价值策略在赛道牛),
低相关策略组合是个人唯一免费的午餐(机构靠杠杆和对冲,个人靠品种内的策略分散)。

竞品证据:果仁网把「策略组合」(多个选股策略按比例配仓)做成了核心付费功能;
QuantConnect Lean 干脆把框架拆成 Alpha(出信号)/ Portfolio Construction(定权重)/ Execution / Risk 四层。
**这是个人量化工具演化的共同终点,不是机构特有需求。**

## jixie 的现状与结构性障碍

- 引擎是单策略世界:`onBar(ctx)` 里信号、仓位、执行揉在一起——单策略这是优点(code-first,少抽象),
  多策略并行时问题出现:**两个策略共享一个账户的现金和 T+1 约束,谁先买谁后买、现金不够听谁的**。
- 主线五(每日信号)如果按单策略设计落地,多策略需求一来就要返工:信号合流、资金冲突仲裁、
  同一标的两个策略一买一卖的对冲抵消,都是信号层的事。
- 6.1(仓位实验室)、6.4(容量测算)、3.4(因子相关性矩阵)都是这层的零件,但没有组合层把它们装配起来。

## 战略方向

### 阶段一:组合视图(纯读,零引擎改动)——建议随主线五一起做

- **策略账本**:每个「上线」策略是一个虚拟子账户(初始资金、独立持仓、独立净值)。主线五的 SignalRun
  按策略生成,信号页从「一个策略的清单」变成「各子账户清单 + 合并清单」。
- **合并清单的仲裁规则(必须在主线五设计时定死,否则返工)**:同标的买卖对冲净额化;现金按子账户预算
  硬隔离(策略 A 超买不许挪用策略 B 的现金——机械系统的资金纪律);合并后按手取整的归属规则。
- **组合净值与相关性**:各子账户模拟净值曲线 + 合并净值;策略间日收益相关性矩阵
  (直接复用 3.4 因子相关性矩阵的计算与热力图基建,把「因子截面相关」换成「策略时序相关」,工程量很小)。

### 阶段二:组合回测(引擎小改)

- 技术方向:**不改 onBar 契约,改外层**。`runStrategy` 已经是纯函数式入口,组合回测 =
  一个 orchestrator 按同一日历驱动 N 个策略实例,每个实例拿自己的虚拟 Portfolio,
  日终把 N 份持仓合并成账户视图。策略代码零感知,「代码即唯一真相」不破。
- 难点提前想清楚:N 个策略共用行情缓存(DataPort 层天然可共享);成本按合并后净单计还是按子账户分别计
  (建议按子账户计,悲观但简单,与「现金硬隔离」一致);涨跌停/停牌约束在子账户层已各自处理。
- 资金分配方案作为组合的「参数」:等权 / 固定比例 / 波动率倒数 / 按容量上限(6.4 的输出直接喂进来)。
  这一步骑在 1.2 参数扫描基建上——分配方案就是一种可扫描参数。

### 阶段三:组合再平衡与退役纪律(远期)

- 子账户间定期再平衡(年度/阈值触发),回测可验证「再平衡是否值得」。
- **策略退役规则**:什么条件下线一个策略(连续 N 月跑输其历史分布?回撤超历史最大 1.5 倍?)。
  这是 6.3(系统健康监控)被搁置后的正确重提形态——对照对象从 bootstrap 分布换成「组合内其他策略 + 自身历史」,
  且决策记录进系统级决策日志(使用原则 6 的产品化,见 04)。

## 明确不做

- 策略间对冲、多空配对——个人 A 股无融券现实,维持机构功能排除。
- 组合优化器(均值方差/Black-Litterman)——对 2~5 个策略是杀鸡用牛刀,等权/波动率倒数足够且稳健。

## 与既有规划的关系

- **主线五设计时必须预留**:SignalRun 挂 strategyId 已自然满足;合并清单与仲裁规则是新增设计点,
  建议写进 `docs/design/daily-signals.md` 的修订版。
- 6.1/6.4/3.4 是本方向的零件;1.2 是阶段二的基建。
- 采纳后建议在 ROADMAP 增设「主线八 · 组合层」,阶段一并入主线五执行。
