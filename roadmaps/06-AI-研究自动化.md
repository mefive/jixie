# 06 · AI 研究自动化:agent 从「帮写代码」到「有纪律的研究闭环」

## 问题陈述与窗口期判断

jixie 的 agent(主线七)已达到的形态——查库、画图、写因子/策略代码、对话流式——在竞品里没有对等物:
BigQuant 的 AI 是模板化选股,聚宽的 AI 助手是文档问答,都没有「工具调用 + 真实数据 + code-first」的组合。
但这个领先是**窗口期**而非护城河:所有平台都在补 LLM 能力,通用 copilot(Cursor 等)也能帮用户写量化代码。

jixie 真正难被复制的组合是:**agent × 研究纪律台账**。别家做 AI 研究助手会撞上「AI 大规模生产回测 =
大规模 p-hacking」的死结(AI 一天试 100 个因子,多重检验把显著性摧毁殆尽);jixie 恰好已经建好了
解这个死结的全套机制——研究卡、holdout 封存、诚实计数、testKey 台账(3.6/3.6a)。
**「能自动研究」很多人会有,「自动研究且统计上诚实」是 jixie 独有的战略位置。**

## 战略方向:三级递进

### 第一级:闭环工具(ROADMAP 已列远期,建议提前)

`runFactorAnalysis` / `runQuickBacktest` 工具让 agent 写完代码自己跑、读结果、自己改。
这是从「代码助手」到「研究助手」的分界线。

技术方向:难点不在工具本身(复用现有 Job/worker 管道),在**长任务进对话流**:
分析要跑几十秒到几分钟,LLM turn 不能挂着等。两个可选形态——
① turn 内轮询(工具返回 jobId,agent 声明「跑起来了」,结果就绪后系统注入后续 turn,近似 marginalia
的任务续接模式);② turn 挂起/恢复(turnBus 已有 snapshot 续接基建,turn 等 job 完成再继续,
用户看到的是一次完整回答)。倾向 ②(体验完整,且 7.5 的两步式 + 后台 runner 结构上已接近),
但需要给 turn 加超时与取消语义。卡片形态沿用「存 spec 不存结果」铁律:分析结果本身已是
FactorReport/Job,卡片只存 reportId 引用。

**纪律接线(本级就要做,不是远期装饰)**:agent 发起的分析必须走与人相同的研究卡机制——
agent 替用户起草研究卡(假设/方向/判据),用户确认后才跑;holdout 封存对 agent 同样生效
(agent 读不到封存结果,prompt 层 + API 层双重保证)。**agent 是研究纪律的适用对象,不是豁免对象。**

### 第二级:研究流程自动化(在纪律轨道上跑得更远)

- **假设 → 报告一条龙**:用户口述一个经济逻辑(「涨停次日打开的股票有惯性」),agent 起草研究卡 →
  写因子 → 探索段分析 → 读报告解读(IC/换手/费后/中性化前后)→ 建议「值得进 holdout / 放弃 + 原因」,
  全程结果进台账。用户角色从操作者上移为**评审者**——这正是「个人是验证者不是发现者」方法论的
  自动化形态:菜单(3.5 三道门)+ 验证流水线(3.6)+ agent 操作员;
- **批量本地化验证**:对 3.5 预置菜单的候选因子,agent 按台账逐个跑三道门证据并起草准入结论草稿,
  人只做最终裁决——把「逐个过三道门」的机械部分交给机器,正是「机械交易系」的自我指涉;
- **报告自动解读**:因子报告/回测结果页加「agent 解读」入口,复用 qa profile + 结构化结果注入,
  输出「这个因子的信号一半是市值换皮」这类 3.5 台账里人写的判断。这也是新手用户(学习清单)的教学界面。

### 第三级:值守型研究(远景,形态开放)

每日信号任务之后,agent 做**日度值守简报**:今日信号异常吗(数量偏离历史分布)、持仓有无异动
(个股大跌/涨停/停牌)、市场状态变化(03 的温度计跨阈值)、在跑的 holdout 有无到期可揭示。
输出一段推送(Notifier 渠道复用)。技术上是 cron + qa profile + 只读工具,难点只在「什么值得说」的
prompt 工程。这一级把 agent 从「被动应答」变成「系统的值班研究员」,是个人系统「一个人 + 一套系统」
愿景的收口形态。

## 风险与红线

- **自动化 p-hacking 是本方向的头号风险**:诚实计数对 agent 发起的实验必须同样累加;考虑给 agent
  加「预算」概念(每假设最多 N 个变体),超了要求 agent 向用户说明为什么还要试;
- **成本**:第二/三级的 LLM 消耗显著上升,DeepSeek 价位下可承受,但应做 token 用量记录(现有 turn
  结构加两列即可),别让研究自动化变成账单惊喜;
- **不做**:AI 全自动上线策略(元决策永远归人,主线六的根)、AI 挖因子农场(与三道门哲学正面冲突)。

## 与既有规划的关系

- 第一级 = ROADMAP 7.8 尾注「远期:runFactorAnalysis/runQuickBacktest」的展开,建议升格为 7.9 正式条目;
- 第二级依赖 3.5/3.6 全套(已具备)+ 第一级;第三级依赖主线五调度 + 03 仪表盘(部分);
- 建议顺序:第一级在主线五之后启动——信号线让系统活起来,研究自动化让系统自己变好,前者优先。
