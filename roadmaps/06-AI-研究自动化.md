# 06 · AI 辅助的可复现量化研究

> 2026-07-25 初版设想 Agent 研究闭环；截至 2026-08-12，查询、SQL、沙盒计算、图表、快速回测和受纪律
> 约束的因子分析已经完成。下一阶段不是让 Agent 试更多模型，而是把对话探索收口成可审查的研究资产。
> 执行状态见根 `ROADMAP.md` 1.1，本文只展开战略边界。

## Agent 的角色

Agent 是研究导师、操作员和审稿助手，不是替用户决定投资的黑箱。它可以：

- 解释理论、指出前置概念并设计复现练习；
- 查询真实数据、写确定性计算、生成图表和检查覆盖；
- 帮助起草假设、反证条件、研究卡和正式定义；
- 运行授权范围内的探索，读取报告并指出替代解释；
- 比较方法与结果，提醒成本、PIT、多重检验和样本外边界。

它不能自动揭示 holdout、批量挖因子、把统计显著包装成投资建议、替用户上线策略或隐藏失败实验。

## 现有基础

- 多轮对话、执行轨迹、刷新续接和取消；
- 只读 SQL、`analyzeData` 沙盒、SQL/计算图卡片；
- 策略和因子代码生成、编译修复；
- `runQuickBacktest` 与受研究卡约束的 `runFactorAnalysis`；
- 结果由服务端确定性计算，原始大数据不经过 LLM。

这些已经构成 notebook-like 研究环境的大半能力。缺口主要在记录结构、可复现性和学习组织，而不是缺少
Jupyter 外观。

## 下一阶段：研究记录

一次值得保留的对话研究应能冻结：

1. 问题、假设、预期方向和推翻条件；
2. 文献/理论来源以及哪些内容只是 Agent 的解释；
3. 查询 spec、计算代码、参数、随机种子和依赖版本；
4. 数据范围、截止日、revision、单位、币种与基准；
5. 表格、图表、统计结果和失败尝试；
6. 结论、限制、替代解释和下一步；
7. 从探索提升为 Factor、Strategy 或正式报告的人工决定。

重新打开时，用户既能阅读当时结果，也能按原 spec 重跑。若结果变化，系统应说明来自数据、代码、参数还是
环境变化，而不是只展示一条新曲线。

## 教学能力

Agent 与公开帮助分工：

- 帮助中心提供稳定、双语、经过审查的概念与操作路径；
- Agent 根据用户问题解释、追问、举例和生成练习；
- 学习地图提供顺序与覆盖范围；
- 研究记录证明用户实际做过什么，而不是只阅读过什么。

Agent 回答金融理论时应尽量区分定义、项目约定、经验事实和推断。需要精确出处时记录来源，不把模型记忆
冒充文献证据。

## 纪律与实验预算

AI 降低试验成本，也会成倍放大 p-hacking。必须保持：

- Agent 发起的变体计入同一实验台账；
- 一轮研究先写假设和判据，再查看结果；
- 同一假设限制实质变体数量，超出时解释原因；
- holdout 与发布权限在 API 层阻断，不只依赖 prompt；
- 失败、无效和无法复现结论都保留；
- 自动摘要不能修改冻结报告中的数值或方法。

## Python 与 TypeScript

Python 已是正式策略表达和研究语言之一，后续可承载 NumPy、pandas、statsmodels、scikit-learn 等生态；
TypeScript Engine 仍是撮合、账户和市场规则的唯一真相。原则是共享数据契约和验证证据，不复制两套引擎。

`analyzeData` 当前使用 JS 是其已实现工具契约，不代表整个项目排斥 Python。是否为对话分析增加 Python
计算后端，要由真实的库需求、沙箱成本和可复现方案触发。

## 可解释机器学习（延后）

未来若研究非线性模型，先满足线性/规则基线、稳定 data revision、walk-forward 和完整研究记录。模型输出
继续作为普通因子或预测信号接受费后、holdout 和风险检验；冻结训练窗口、特征、超参数、随机种子和模型版本。

不做端到端价格预测竞赛，不让 AutoML 自动搜索绕过实验计数，不以 feature importance 单独冒充因果解释。

## 当前不做

- AI 全自动研究、全自动发布或全自动上线；
- 为模仿 Notebook 单独复制一套与 Agent 平行的页面和存储；
- 把 LLM 生成的数据、图形点位或绩效数字当成正式结果；
- 隐藏工具失败、数据缺失或对结论不利的结果；
- 用“智能”命名代替明确的数据、方法和权限边界。
