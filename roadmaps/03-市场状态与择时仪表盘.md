# 03 · 市场状态与择时仪表盘（境内阶段历史设计）

> **2026-08-12 状态**：本文提出的境内市场状态、估值和历史回放主体已经完成，详细实况见
> `docs/design/market-state.md` 与根 `ROADMAP.md` 的完成基础。本文保留为设计来源，不再代表当前待办。
> 新阶段若扩展香港、美国或全球资产状态，必须先完成跨市场日历、币种、基准和 PIT 数据契约，不能把本文
> 的 A 股指标直接复制过去。

## 问题陈述

目标两阶段趋势策略的第一阶段就是**全市场广度择时**——但今天 jixie 里没有任何「市场层面」的视图:
系统只认识个股截面,不认识「市场现在是什么状态」。同时,竞品里黏性最高的个人工具恰恰是这类
「每天看一眼」的市场温度计:理杏仁的全市场 PE/PB 百分位、股债性价比,集思录的品种轮动数据,
都是让用户每天回来的钩子。

对机械交易系统,市场状态还有一层纪律价值:回撤中回答「是我的系统坏了,还是市场整体在跌」,
需要一个客观的市场状态参照系；这比用短实盘期统计量判断“系统是否失效”更朴素、可解释。

## 战略方向:一条「市场感知」能力线,两个出口

数据在库里基本都有(daily / daily_basic / index 日线 / moneyflow),这条线**几乎纯是计算和呈现**,
没有数据采购障碍。两个出口:

### 出口一:SDK 原语(服务策略代码,code-first 本命)

策略里能直接写广度择时,才算把目标策略正确表达出来。方向性 API(命名届时按 SDK 规范定):

- `ctx.market.breadth(...)`:全市场/指数成分内,N 日新高-新低占比、收盘价在 MA20/MA60 上方占比;
- `ctx.market.valuation(...)`:指数级 PE/PB 及其历史分位(基于 daily_basic 聚合);
- `ctx.index(...)` 已有指数日线基础上,补指数的均线/动量惯用判断。

技术方向:这类指标是「全市场逐日聚合」,逐 bar 现算会打爆性能,应当走**预计算表**
(新 Prisma 表,如 `MarketIndicator`,按日一行多列,随每日同步顺带增量计算;引擎侧 preload 进 DataPort,
墙内零查询)。这与 FactorValue 预计算的既有模式一致,幂等按日重算。别忘了同步 SQL 白名单表文档。

### 出口二:市场仪表盘页(每天看一眼的首页)

一个只读页面,回答三个问题:

1. **温度**:全市场估值分位(等权/加权 PE、PB 的 10 年分位)、破净率、股债性价比(1/PE − 10 年国债,
   国债收益率需要一个小数据源,见 05);
2. **广度**:上方占比 / 新高新低线 / 涨跌家数,叠加用户策略用的那条广度阈值线(和策略同一口径,
   看图即知「系统现在开着还是关着」);
3. **结构**:大小盘剪刀差(中证1000/沪深300 相对强弱)、价值成长轮动、换手率集中度(拥挤度雏形——
   成交额前 5% 个股占全市场成交比重,拥挤度同时是 3.5 因子研究的输入)。

技术方向:页面 = 预计算表 + echarts,复用 7.6 图表基建的 buildOption;不做实时盘中刷新(日频系统,
收盘后更新一次,与信号任务同一调度)。

### 顺带解锁的研究能力

- **Regime 标注回测**:有了逐日市场状态序列,回测结果页可按状态分段统计(牛/熊/震荡下各自的收益回撤),
  直接强化「使用原则 4:看跨行情结构的表现」;实现只是结果分析层按日期 join 状态序列,引擎零改动。
- 择时研究本身可走因子管道:把「广度指标」当作时序信号做事件研究(信号发出后指数未来 N 日收益分布),
  与 08 的事件研究基建共享。

## 明确不做

- 盘中实时数据、Level-2、情绪爬虫(股吧/雪球舆情)——数据成本与可靠性都不配日频系统;
- 宏观预测模型——温度计只陈述现状分位,不输出预测(平台中性,不预设风格)。

## 与既有规划的关系

- 直接服务用户主径策略(使用原则 1),建议优先级排在主线五之后、与其共享每日调度基建;
- 股债性价比需要国债收益率单表(小体量数据需求,归入 05 的波次清单);
- 采纳后建议进 ROADMAP 新主线或挂在主线六下(它本质是「纪律工具」的市场参照系)。
