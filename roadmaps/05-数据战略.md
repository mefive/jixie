# 05 · 数据战略:单源风险、版本化与 PIT 深化

## 问题陈述

数据层是「可信度地基之下的地基」(4.7 原话)。当前三个战略级弱点:

1. **单源依赖**:全部数据来自 Tushare 一家(积分制、限频、接口偶有口径变更),它挂掉或改价,系统停摆;
2. **数据版本化未落地**:`dataRevision` 在 3.6 的 variantKey 里预留了位置但恒为空——数据修正
   (Tushare 回补/更正历史数据)会让「相同输入应复现相同输出」静默失效,研究纪律台账有一条暗缝;
3. **PIT 覆盖有边界**:财务只有 fina_indicator 单表,应计类因子(3.5 台账里明确「缺数据不做」)、
   现金流质量因子被挡在门外;历史 ST/退市状态缺失已在 3.6b-A 里诚实标注「未过滤」。

竞品对照:优矿的唯一护城河是通联数据;Qlib 把数据版本化做进了框架(数据目录带版本号)。
数据是慢变量——补一段历史数据的成本随时间线性上涨(限频),**早布局的收益是复利的**。

## 战略方向

### 方向一:备源校验,不做双源合并(务实版冗余)

全面双源(每表两来源自动对账合并)工程浩大且引入新错误面。务实形态:

- **akshare 作为免费校验源**:审计脚本(4.7)抽样若干股票×日期,对照 Tushare 落库值与 akshare
  现值(收盘价/复权因子/市值),偏差超阈值报警——花小钱(一个 Python 脚本或 HTTP 直调)买「单源静默出错」
  的检测能力,不买合并能力;
- **落库即资产**:坚守既有宗旨「抓来的数据必须落库、同步幂等可续传」,库本身就是对上游最好的对冲
  (Tushare 死了,历史还在,只断增量);4.6 备份的「推离本机」待办应尽快执行,它是本方向的一部分;
- 触发升级条件:若未来 Tushare 关键接口涨价/停服,再评估整表迁移到 akshare/baostock,届时同步层
  (`src/tushare` → `src/store`)的接口抽象是唯一改动面——现有分层已经把这个风险隔离得不错。

### 方向二:dataRevision 落地(研究纪律的补口)

技术方向:不追求逐行血缘(过度工程),用**表级同步水位**:每次 sync 完成记录
`(table, syncRange, rowCount, syncedAt)` 到同步日志表,`dataRevision = 各相关表最新水位的摘要 hash`。
报告固化它之后,「同 spec 同代码不同结果」可以归因到「数据动了」而非「系统坏了」。
配套一个「数据变更对研究的影响」提示:重跑历史报告 variantKey 不同时,UI 说明是 dataRevision 变了。
成本低(一张表 + hash 拼接),补上 3.6 台账的最后一条缝。

### 方向三:PIT 深化的波次清单(需求拉动排序,不囤)

维持 4.2「有策略/因子想用了再加」的铁律,但把候选排好队(按解锁的研究价值排序):

1. **资产负债表 + 现金流量表关键列**(Tushare balancesheet/cashflow):解锁应计因子(质量族里
   文献证据最强的之一,3.5 台账两次提到「缺数据不做」)、净营运资产、资本开支——这是当前最大的研究面扩展;
   技术上完全复用 fina_indicator 的 as-of 管道(annDate PIT + `ctx.history` 财务字段机制已在 3.5 打通);
2. **历史 ST/风险警示状态**(namechange 接口可重建):补 3.6b-A 诚实标注的「未过滤」缺口,
   让股票池过滤真正 PIT 化;
3. **国债收益率**(单表小体量):解锁股债性价比(03 依赖);
4. **北向资金/融资融券**:仅当 3.5 下一批因子候选真的排到资金流主题扩展时;
5. **概念板块**:优先级最低——口径混乱、事后构建偏差重,研究价值存疑。

### 方向四:审计常态化(4.7 从待做变机制)

4.7 的脚本做出来后,建议直接挂进每日同步任务尾部(轻量子集:当日行数对照 + 关键列空值率),
全量审计月度跑。审计报告落库留痕,与 dataRevision 同一张同步日志表体系——
「数据质量」从一次性脚本变成持续机制,才配得上研究线已经达到的纪律水平。

## 明确不做

- 分钟/tick/L2(拍定);另类数据爬虫(舆情/电商/卫星图——个人零优势且法律灰色);
- 自建行情采集(交易所直连/爬实时行情)——可靠性成本远超 Tushare 订阅费;
- 全表双源自动合并(见方向一,只做校验)。

## 与既有规划的关系

- 方向二/四是 3.6、4.7 的直接补强,建议并入对应条目;方向三是 4.2 的排序细化;
- 方向一新增,建议进 ROADMAP 4.x 一条「数据备源校验」;
- 4.6 备份的「离机」待办在本文档语境下升级为战略必做(数据资产化的前提)。
