# 继续修改策略并重新运行

生成策略后，可以在左侧继续说明要改什么。每次修改完成后，都要核对中间的代码，再运行回测。对话回复表示修改请求已经处理，不表示新的回测结果已经产生。

## 提出明确修改

好的修改要求应同时包含：

- 要修改的字段或规则。
- 新值或新条件。
- 哪些规则保持不变。

例如：

`把每月买入数量改为200股，其他规则不变。`

避免只写“再优化一下”。页面无法从这句话判断应改收益目标、风险、频率、数量还是证券。

## 查看修改是否生效

1. 在左侧底部输入修改要求。
2. 按回车键发送。
3. 等待新的回复完成。
4. 在中间代码中找到修改位置。
5. 确认其他关键规则没有被意外改变。
6. 点击“运行回测”。

下图中的标记分别是：

1. 本策略的完整对话。
2. 本次修改的回复。
3. 修改后的代码，其中买入数量已经从 100 变为 200。
4. 需要再次点击的“运行回测”按钮。

![继续对话后买入数量从100股修改为200股](/help/zh/backtesting/strategy-revised-01.png)

如果回复说已经修改，但代码仍是原值，不要运行。重新说明具体数值，并指出代码中仍不正确的内容。

## 为什么必须重新运行

代码变化不会自动计算新结果。修改后：

- “运行回测”按钮会重新变为可用。
- 页面上原有指标仍属于上一次运行。
- 离开策略时会提示“有改动尚未运行”。
- 只有新回测完成后，结果才对应新代码。

需要保留修改时，先运行回测；不需要时才选择“放弃改动”。

## 检查修改后的结果

下图是 200 股版本完成后的真实回测：

1. 本次使用的日期和资金。
2. 新结果的收益、风险、成本和成交指标。
3. 交易明细和本次成交笔数。
4. 本次运行日志。

![修改买入数量并重新运行后的指标、成交笔数和日志](/help/zh/backtesting/strategy-revised-result-01.png)

检查顺序：

1. 确认回测已经完成。
2. 查看成交笔数是否符合修改后的规则。
3. 打开交易明细确认数量为 200 股。
4. 比较修改前后的收益、回撤、费用和换手。
5. 记录本次修改内容和设置。

示例策略规定已经持有时不重复买入，因此五年区间内只有首次买入一笔。成交少是规则本身的结果，不表示页面漏算了每个月。

## 一次修改多项规则

同时修改证券、日期条件、数量和退出规则，会很难判断结果变化来自哪里。建议：

1. 每次只改一个主要规则。
2. 运行并记录结果。
3. 再进行下一项修改。

如果确实需要一次改多项，应在要求中逐条列出，并逐项核对代码。

## 修改后结果变差

这不表示修改没有生效。先检查：

- 代码是否准确执行新规则。
- 成交数量和日期是否改变。
- 费用和滑点是否增加。
- 回测区间和资金是否一致。
- 原结果是否只是特定参数下的偶然表现。

不要反复修改参数直到历史收益最高，再把这一组当作可靠结论。
