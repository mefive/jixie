# 恢复运行任务和处理失败

回测运行时可以刷新页面。重新打开同一策略后，页面会查询该策略正在运行的任务，并继续显示状态和日志。

## 刷新后恢复任务

1. 确认当前策略已经提交回测。
2. 刷新页面，或重新打开同一个策略。
3. 等待策略名称和代码加载。
4. 查看结果区域是否显示“回测计算中”。
5. 查看日志是否继续更新。
6. 等待本次任务完成，不要再次点击“运行回测”。

下图是在任务运行中刷新后的页面：

1. 当前策略名称。
2. 恢复后的运行状态。
3. 继续显示进度的日志区域。

![回测运行中刷新页面后的任务恢复状态](/help/zh/backtesting/reconnect-01.png)

短时间只看到“正在启动回测进程”是正常的。任务是否完成，应以最终指标、图表和日志完成信息为准。

## 长时间没有变化

依次检查：

1. 日志是否仍在增加。
2. 顶部按钮是否仍是运行状态。
3. 刷新后是否仍打开同一个策略。
4. 日期范围是否很长，或策略是否需要处理大量证券。

需要反馈问题时，记录策略名称、日期范围、刷新时间和日志最后一行。不要连续提交相同回测，这会产生多个无必要的任务。

## 运行失败

失败时，结果区域会显示本次任务的错误。下图中的标记分别是：

1. 当前参与运行的策略代码。
2. 回测失败信息。
3. 日志区域。

![策略代码无法编译时的回测失败信息](/help/zh/backtesting/failure-01.png)

处理失败的步骤：

1. 先阅读结果区域的第一条错误。
2. 打开日志查看失败前最后几行。
3. 检查代码是否完整，括号和引号是否配对。
4. 检查证券代码、日期、资金和参数是否有效。
5. 修正后重新运行。
6. 确认结果完成时间和设置对应本次修改。

## 常见失败原因

- **代码编译失败**：代码不完整、符号缺失或写法不受支持。
- **没有所需数据**：证券代码错误，或日期范围内没有足够历史数据。
- **参数无效**：日期顺序、资金、数量或策略参数不符合要求。
- **计算时间过长**：区间很长、证券很多或每天进行了大量重复计算。

失败不等于策略亏损。它表示本次回测没有得到可用结果，不能用之前留在页面上的指标代替。
