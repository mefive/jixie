# Ingestion 数据采集

`pnpm data ingest [--to YYYYMMDD]` 从各数据集约定起点推进到固定目标；省略日期时取启动时的上海自然日。下载和字段接纳归 Market，执行、事务、恢复与诊断归 Ingestion。

| 阅读入口 | 职责 |
| --- | --- |
| `cli/data.ts`、`cli/execute.ts` | 参数、环境、命令输出及连接收尾 |
| `plan.ts` | 自然范围、稳定批次、对象轮换 |
| `ingest.ts` | 单写者、整批下载、短事务和中断恢复 |
| `reset.ts` | 备份后清空业务数据，保留四张认证表 |
| `status.ts`、`routes.ts`、`middleware.ts` | `/api/ingestion/status`、部署版本与真实发布锁门禁 |

`IngestionRun` 记录一轮，`IngestionBatch` 记录一次尝试，`IngestionIssue` 保存错误及来源警告的原始内容，`IngestionSelection` 保存 ETF／指数名单。成功批次只表示本次响应已处理，不产生全市场数据资格。三张财报从 1988 年按公告日区间获取全市场数据，按报表类型 1／4／5 分批，再补查缺少覆盖证据的实际公告日。财务指标使用逐季全市场 VIP 查询。空响应可以建立覆盖，已入选证券的上市前报告仍保留。

ETF 以每个历史开市日的当日规模选取最多 100 只，与已有名单合并去重，再补齐累计标的的有效历史；名单允许超过 100。每个选取日期独立保存恢复收据，不用最终目标日或今天的名单代替历史排名。Run 是逻辑采集任务。同一目标最近 Run 未完成时恢复其 ID，跳过该 Run 已成功的所有批次；失败、partial、中断与未尝试批次继续执行。完成后新建 Run，才重新获取目录、历史名称、财报与财务指标并幂等接纳。已成功的历史行情按日期补缺；没有刷新频率、策略版本或另一套覆盖状态。价格、复权、估值与限价独立采集。股票按 SSE、SZSE、BSE 各自日历中的开市日期选择范围，不借用其他交易所的日历；上市早于日历可得范围或日历未提供某日，均正常跳过、不补自然日、不报错。

分页全部完成后才写业务表。业务数据、未接纳问题、批次终态和数据 revision 在同一事务提交；失败或截断不写已下载的半批。独立合法记录可以与未接纳记录一起提交，完整快照保持对象原子性。强杀后在原 Run 新增未完成批次的尝试记录，不清理已提交的合法数据或旧诊断。摘要和状态只将当前计划最近尝试的 error 作为未解决问题；warning 单独统计，不影响完成。旧逐证券收据保留，新全市场报告期批次首次仍需下载，不能直接转换覆盖范围。

`pnpm data runs [--limit N]` 查看最近运行（默认 5，允许 1–100；仅返回 id、status、startedAt、finishedAt），`pnpm data issues RUN_ID` 查看完整问题。正常过滤和来源无记录不当作来源错误；记录不含凭证。产品可用性只受实际发布争用影响。未完成 Run 的成功明细不压缩；已完成运行保留最近 20 轮明细，较早重复收据在不丢失恢复范围和来源起点时压缩；问题及关联批次不删除。

重建使用 `pnpm data reset` 预览、`--apply` 备份后执行；仅保留 `User`、`Session`、`InviteCode`、`EmailLoginChallenge`。部署首次切换使用持久标记完成一次业务重建，失败保持 API 停止；不搬移旧维护凭证，不在部署时触发全历史下载。

设计与人工审阅入口见 [Ingestion 设计](../../../../docs/design/ingestion.md)。行为测试、构建和实际工作库重建须在代码审阅通过后执行。

上市日晚于本轮截止日的股票／ETF 正常跳过，不采行情、财务指标、财报或分红，不报范围错误；上市当天纳入。已上市公司的上市前财报仍完整保留，不按 IPO 日期截断报告期。ETF 未来目录记录先过滤，再校验交易属性。ETF 空名单不关闭自动历史选取，指数保留已有显式配置。

股票日数据仍按交易日分批，daily／adj_factor／daily_basic 使用 6000 条分页，stk_limit 使用 5800 条分页；满页继续获取终止页。HTTP 请求允许重叠，发起间隔默认至少 800ms，准备与入库保持串行。本次索引迁移仅解除同 Run 逻辑批次的唯一限制，不修改业务数据。OHLC 范围关系按下述来源警告处理，其他接纳规则保持。


OHLC 范围矛盾作为来源 warning：股票和 ETF 保留原始正值有限价格，诊断保存 `severity=warning`、证券／日期与完整来源行；警告与业务数据、成功批次同事务提交，不增加未接纳数量。其他硬校验保持。`pnpm data issues RUN_ID` 可按返回的 severity 区分 warning／error；Run 摘要的 issues 只计错误，warnings 单独计数，旧错误仍保留历史。


财报窗口用 `start_date/end_date` 按 `ann_date` 查询。初始窗口覆盖完整连续缺口，满 5000 行后保存不重叠的子计划；各完整子区间独立提交，单日仍满页时记为未完整响应。窗口收据保留实际查询的父区间、子区间和完整字段。公告标签扫描止于目标日期，不提前扫描未来公告。披露日取 ann_date 与 f_ann_date 最晚者，可得日为其后首个交易日。各窗口的请求开始日期用于保守判断旧版本可能在哪一天新增，抓取当日保留补查机会。记录按来源指纹追加，旧报告期修订使用其实际可得日。

财报计划在 Run 快照保存本轮证券名单，跨 Run 复用要求请求、范围、完整响应和证券范围可验证。未来报告期被延后接纳的窗口在目标推进时重新核对。旧季度收据、逐股收据及数据继续保留，旧逐日收据按各自字段复用。显式 `runs retry` 可一次性升级中断副本的财报计划，保留成功单元及有诊断的单元。没有历史覆盖的新证券通过有目标边界的公告区间补采，保留合法旧逐股收据。来源沿用旧公告日期静默改值的情况仍需定向复核。


分红来源字段补齐时，恢复会检查成功收据里的实际请求字段；缺少送转或实施日期字段的旧分红批次补采一次，完整字段成功收据继续复用。旧收据不删除、不改状态，其他成功数据不重新下载。分红来源按分配形态区分独立记录，现金实施去重归 Market 规则和 Research 显式读取，不修改复权因子。

分红首次按证券补完整历史。有效的完整字段收据包含成功空响应，以及来源响应完整且问题已确认保留或修复已核验的批次。已有基线的证券进入全市场日期增量，每个自然日分别采 `ann_date` 和 `imp_ann_date`，按原有分红身份合并命中记录。日期切片保留未出现在响应中的历史行。目标内已结束的日期可复用已生效的收据，遇到分页截断整批重试。早于日期查询支持范围的缺口仍按证券补齐。

采集结束后，按 [修复 Agent Prompt](../../../../docs/prompts/ingestion-issue-repair.md) 使用 `pnpm data issues export RUN_ID --out FILE [--issue ISSUE_ID]` 一次取得诊断、业务字段和修复契约。Agent 生成业务 JSON 计划，调用 `pnpm data issues repair --plan FILE` 预览，获准后加 `--apply --expect-plan PLAN_HASH` 提交。完整流程见 [导出与修复设计](../../../../docs/design/ingestion-issue-export.md)。

[问题处理与数据状态](../../../../docs/design/ingestion-issue-resolution.md)：Run 结束时同事务补齐有效问题的 pending。历史运行通过 `pnpm data issues reconcile [RUN_ID]` 幂等补齐。CLI 在修复事务内登记 resolved／accepted 或重开为 pending，前端和导出共同读取处理结果。已经修复的字段被覆盖时提示复核。


副本采集使用同一 Run ID 串联采集、候选修复和人工发布。使用 `pnpm data runs inspect RUN_ID` 查看候选版本。维护者核验后用 `pnpm data runs accept RUN_ID --expect-candidate HASH` 发布，或用 `pnpm data runs reject RUN_ID --reason REASON` 拒绝。进程异常退出时，确认旧命令已结束后运行 `pnpm data runs recover RUN_ID --confirm-stopped`。详见 [副本采集计划](../../../../docs/design/ingestion-replica-plan.md)。

`runs inspect` 同时返回 Run 的起止时间和 `batches`。每次实际尝试独立列出，`elapsedMs` 为批次结束时间减开始时间，尚无结束时间时为 `null`。未发布时从就绪副本读取，发布后从主库读取。副本尚未就绪或已拒绝时没有批次可读，历史运行只返回仍保留的记录。

管理员或开发环境用户也可从数据状态弹窗接收副本。`GET /api/ingestion/runs/:runId` 返回候选版本和采集摘要，`POST /api/ingestion/runs/:runId/accept` 接受 `expectedCandidateVersion`。两个入口校验会话和服务端发布权限，发布入口位于业务读取门禁之外，复用 `acceptCandidate` 的版本校验、并发状态切换及发布锁。

`pnpm data runs retry RUN_ID` 显式重试待修复或已中断副本的未成功批次，复用固定目标、计划和成功收据。源请求失败修正后用该命令补采，旧诊断作为历史保留。重试完成后重新检查副本并由维护者接收。

指数权重保留按月的计划单元，请求使用该窗口内经完整 SSE 日历核实的最后交易日 `trade_date`。月中截止时查询范围内日期，完整空响应保留之前的权重快照。分页全部完成后才接纳完整快照。


支持区间的日历、ETF／指数序列和名称不再按年切割；财报不再按月切割。旧完整成功收据按实际范围并集补缺。满页探测使用 `split` 状态，记录耗时但不写业务行；同事务保存子计划，恢复时跳过已成功子区间。当前摘要统计叶子计划，inspect 保留所有实际尝试。日历在实际捕获当日及未来部分继续刷新，允许为可得日定位有限前瞻；财报公告范围严格止于 to。旧 Run 已冻结的未升级单元继续保留原有请求和恢复语义。


并发下载见 [设计](../../../../docs/design/ingestion-concurrency.md)。CLI 默认最多 4 个下载任务和 8 个未提交批次，原始响应按 64MiB 字节高水位缓冲，溢出页面临时落盘；按固定计划顺序回放、准备并串行提交。`runs inspect.batches[].execution` 返回真实 HTTP 起止、下载、限流、待入库、准备和写入耗时及 HTTP／重试次数，旧批次为 null。正常暂停取消网络、等待队列和未提交结果，等待在途任务收尾后才释放 Run；成功批次继续作为唯一恢复凭据。
