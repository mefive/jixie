# Ingestion 数据采集

`pnpm data ingest [--to YYYYMMDD]` 从各数据集约定起点推进到固定目标；省略日期时取启动时的上海自然日。下载和字段接纳归 Market，执行、事务、恢复与诊断归 Ingestion。

| 阅读入口 | 职责 |
| --- | --- |
| `cli/data.ts`、`cli/execute.ts` | 参数、环境、命令输出及连接收尾 |
| `plan.ts` | 自然范围、稳定批次、对象轮换 |
| `ingest.ts` | 单写者、整批下载、短事务和中断恢复 |
| `reset.ts` | 备份后清空业务数据，保留四张认证表 |
| `status.ts`、`routes.ts`、`middleware.ts` | `/api/ingestion/status`、部署版本与真实发布锁门禁 |

`IngestionRun` 记录一轮，`IngestionBatch` 记录一次尝试，`IngestionIssue` 保存错误及来源警告的原始内容，`IngestionSelection` 保存 ETF／指数名单。成功批次只表示本次响应已处理，不产生全市场数据资格。财报与财务指标固定从 1988 年逐季通过 VIP 接口下载全市场，财报区分种类与报告类型 1／4／5；不扫描财务目录、不按证券拆分，不提供用户起点参数。目标内的空季度正常成功，已入选证券的上市前报告在这一范围内仍保留。

ETF 以每个历史开市日的当日规模选取最多 100 只，与已有名单合并去重，再补齐累计标的的有效历史；名单允许超过 100。每个选取日期独立保存恢复收据，不用最终目标日或今天的名单代替历史排名。Run 是逻辑采集任务。同一目标最近 Run 未完成时恢复其 ID，跳过该 Run 已成功的所有批次；失败、partial、中断与未尝试批次继续执行。完成后新建 Run，才重新获取目录、历史名称、分红、财报与财务指标并幂等接纳。已成功的历史行情按日期补缺；没有刷新频率、策略版本或另一套覆盖状态。价格、复权、估值与限价独立采集。股票按 SSE、SZSE、BSE 各自日历中的开市日期选择范围，不借用其他交易所的日历；上市早于日历可得范围或日历未提供某日，均正常跳过、不补自然日、不报错。

分页全部完成后才写业务表。业务数据、未接纳问题、批次终态和数据 revision 在同一事务提交；失败或截断不写已下载的半批。独立合法记录可以与未接纳记录一起提交，完整快照保持对象原子性。强杀后在原 Run 新增未完成批次的尝试记录，不清理已提交的合法数据或旧诊断。摘要和状态只将当前计划最近尝试的 error 作为未解决问题；warning 单独统计，不影响完成。旧逐证券收据保留，新全市场报告期批次首次仍需下载，不能直接转换覆盖范围。

`pnpm data runs [--limit N]` 查看最近运行（默认 5，允许 1–100；仅返回 id、status、startedAt、finishedAt），`pnpm data issues RUN_ID` 查看完整问题。正常过滤和来源无记录不当作来源错误；记录不含凭证。产品可用性只受实际发布争用影响。未完成 Run 的成功明细不压缩；已完成运行保留最近 20 轮明细，较早重复收据在不丢失恢复范围和来源起点时压缩；问题及关联批次不删除。

重建使用 `pnpm data reset` 预览、`--apply` 备份后执行；仅保留 `User`、`Session`、`InviteCode`、`EmailLoginChallenge`。部署首次切换使用持久标记完成一次业务重建，失败保持 API 停止；不搬移旧维护凭证，不在部署时触发全历史下载。

设计与人工审阅入口见 [Ingestion 设计](../../../../docs/design/ingestion.md)。行为测试、构建和实际工作库重建须在代码审阅通过后执行。

上市日晚于本轮截止日的股票／ETF 正常跳过，不采行情、财务指标、财报或分红，不报范围错误；上市当天纳入。已上市公司的上市前财报仍完整保留，不按 IPO 日期截断报告期。ETF 未来目录记录先过滤，再校验交易属性。ETF 空名单不关闭自动历史选取，指数保留已有显式配置。

股票日数据仍按交易日分批，daily／adj_factor／daily_basic 使用 6000 条分页，stk_limit 使用 5800 条分页；满页继续获取终止页。请求保持串行与 800ms 最小间隔。本次索引迁移仅解除同 Run 逻辑批次的唯一限制，不修改业务数据。OHLC 范围关系按下述来源警告处理，其他接纳规则保持。


OHLC 范围矛盾作为来源 warning：股票和 ETF 保留原始正值有限价格，诊断保存 `severity=warning`、证券／日期与完整来源行；警告与业务数据、成功批次同事务提交，不增加未接纳数量。其他硬校验保持。`pnpm data issues RUN_ID` 可按返回的 severity 区分 warning／error；Run 摘要的 issues 只计错误，warnings 单独计数，旧错误仍保留历史。


1988—2018 年共 124 个季度：1116 个财报批次与 124 个指标批次。恢复旧目录式 Run 时重建其季度计划并保留全部历史记录，旧目录失败不再作为当前未完成任务；已成功的季度收据仍然复用。当前改动不新增数据库迁移，正常数据源请求均明确传入 period。


分红来源字段补齐时，恢复会检查成功收据里的实际请求字段；缺少送转或实施日期字段的旧分红批次补采一次，完整字段成功收据继续复用。旧收据不删除、不改状态，其他成功数据不重新下载。分红来源按分配形态区分独立记录，现金实施去重归 Market 规则和 Research 显式读取，不修改复权因子。

采集结束后的问题分析与修复 SQL 提案见 [通用 Prompt](../../../../docs/prompts/ingestion-issue-repair.md)。[CLI 导出设计](../../../../docs/design/ingestion-issue-export.md)约定导出当前有效问题、表结构及必要业务上下文，Agent 分析导出文件；`pnpm data issues export RUN_ID --out FILE [--issue ISSUE_ID]` 导出诊断包，原有 `data issues RUN_ID` 继续返回全部历史诊断。Agent 读取导出文件分析，修复 SQL 由维护者另行审阅执行；导出器通过正式 CLI 读库，不进行业务写入。


诊断导出为只读操作，有 error／warning 仍正常返回 0；原始记录、当前业务行和实际表结构保存在一个带版本的 JSON 中，默认只选当前有效问题，历史诊断身份及原因单列。无批次问题或计划／来源身份不足时保留未知状态。输出路径相对 CLI 工作目录解析，已有文件不覆盖，文件权限 0600；命令、参数和示例同时见 `cli/data.ts` 入口注释及 `--help`。导出不修改接纳规则、旧诊断或市场 revision，不执行修复 SQL。
