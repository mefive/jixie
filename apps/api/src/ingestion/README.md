# Ingestion 数据采集

`pnpm data ingest [--to YYYYMMDD]` 从各数据集自然起点推进到固定目标；省略日期时取启动时的上海自然日。下载和字段接纳归 Market，执行、事务、恢复与诊断归 Ingestion。

| 阅读入口 | 职责 |
| --- | --- |
| `cli/data.ts`、`cli/execute.ts` | 参数、环境、命令输出及连接收尾 |
| `plan.ts` | 自然范围、稳定批次、对象轮换 |
| `ingest.ts` | 单写者、整批下载、短事务和中断恢复 |
| `reset.ts` | 备份后清空业务数据，保留四张认证表 |
| `status.ts`、`routes.ts`、`middleware.ts` | `/api/ingestion/status`、部署版本与真实发布锁门禁 |

`IngestionRun` 记录一轮，`IngestionBatch` 记录一次尝试，`IngestionIssue` 保存失败及未接纳原始内容，`IngestionSelection` 保存 ETF／指数名单。成功批次只表示本次响应已处理，不产生全市场数据资格。财报和财务指标每次按证券完整获取，不向来源传开始日期或报告期；下载后按目标日期过滤，不截断上市前报告。

目录、历史名称、分红、财报与财务指标每轮重取并幂等接纳。已成功的历史行情按日期补缺；没有刷新频率、策略版本或另一套覆盖状态。价格、复权、估值与限价独立采集。股票按 SSE、SZSE、BSE 各自日历中的开市日期选择范围，不借用其他交易所的日历；上市早于日历可得范围或日历未提供某日，均正常跳过、不补自然日、不报错。

分页全部完成后才写业务表。业务数据、未接纳问题、批次终态和数据 revision 在同一事务提交；失败或截断不写已下载的半批。独立合法记录可以与未接纳记录一起提交，完整快照保持对象原子性。强杀后重试未完成批次，不清理已提交的合法数据。

`pnpm data runs` 查看最近运行，`pnpm data issues RUN_ID` 查看完整问题。正常过滤和来源无记录不当作来源错误；记录不含凭证。产品可用性只受实际发布争用影响。成功明细保留最近 20 轮，较早重复收据在不丢失恢复范围和来源起点时压缩；问题及关联批次不删除。

重建使用 `pnpm data reset` 预览、`--apply` 备份后执行；仅保留 `User`、`Session`、`InviteCode`、`EmailLoginChallenge`。部署首次切换使用持久标记完成一次业务重建，失败保持 API 停止；不搬移旧维护凭证，不在部署时触发全历史下载。

设计与人工审阅入口见 [Ingestion 设计](../../../../docs/design/ingestion.md)。行为测试、构建和实际工作库重建须在代码审阅通过后执行。
