# 保留数据的最小同步

唯一日常写入口是 `pnpm data sync [--to YYYYMMDD]`，人工存量修复使用 `pnpm data clean`，管理员另用 ETF／指数名单 CLI。省略目标时固定启动时的上海自然日；帮助和非法参数不读环境、不连接数据库。源码入口 [cli/data.ts](cli/data.ts)，生产入口 `dist/src/maintenance/cli/data.js`。

| 阅读入口 | 职责 |
| --- | --- |
| [cli/data.ts](cli/data.ts) / [cli/execute.ts](cli/execute.ts) | 参数、环境、摘要、退出及连接收尾 |
| [clean.ts](clean.ts) / [cli/clean.ts](cli/clean.ts) | 人工预览、备份、原子清理与覆盖失效；项目见 [命令索引](../../scripts/README.md#人工数据清理) |
| [sync.ts](sync.ts) / [attempt.ts](attempt.ts) / [publication.ts](publication.ts) | 写者所有权与轮换／一次实际尝试／短事务发布 |
| [partitions.ts](partitions.ts) | 每次选择一个近期窗口或最早历史缺口，不写计划 |
| [status.ts](status.ts) / [routes.ts](routes.ts) | 当前名单覆盖、运行与真实发布争用 |
| [Market policies](../market/synchronization/policies.ts) / [scopes](../market/synchronization/scopes.ts) | 16 个数据集的时期、来源规则、名单及上市／退市边界 |
| [Market prepare](../market/synchronization/prepare.ts) / [rows](../market/synchronization/rows.ts) | 显式领域分派、纯内存缺值合并；各领域 `write.ts` 用有类型的 Prisma 写自己的表 |

先更新日历与目录，再轮换数据集。一次轮到某数据集，最多一个近期窗口和一个历史缺口；对象按上次实际尝试时间轮换，失败也记时间。同窗口每轮最多尝试一次，来源内部可有限重试。取消整轮窗口数、HTTP 请求数和时长上限，直到固定目标内没有未尝试窗口或收到取消；单次 HTTP 超时、限流、有限重试和重复分页检查保留。最近运行摘要记录下个数据集位置，只保留当前和上次运行。

近期修订范围与来源刷新频率沿用 policies。已完成且超出近期范围的历史不再自动巡检；未完成历史仍补齐。管理员可用较早 `--to` 重取附近历史，不截断已存较新数据。没有比例预算、多级持久退避、预写 pending 队列或计划游标。

`DatasetSyncPartition` 只记录真实尝试的边界、状态、缺口、错误和时间；`DatasetSyncState` 只保留两个轮换时间、最大观察日和连续 `verifiedThrough`。pending 是已尝试未完成数，零 pending 不代表全部历史完整。覆盖从当前有效的完成窗口推导；失败重查撤销重叠旧资格，保留合法值。正式消费者按用途调用共享资格检查；股票、ETF、指数序列都复核日历的完整覆盖，股票辅助数据还依赖当日价格资格。

未返回字段和未知 null 保留旧值，明确清空的 null 才可覆盖。部分响应保存合法独立记录，完整成分快照和财报对象保持原子；只有已核验完整的精确范围可删除缺席记录；历史名称只更新明确返回的区间，不用缺席推断删除。分红当前值捕获时间直接存 Dividend.observedAt／availabilityQuality；同值重抓和代码接续保留原时间，真实修订更新捕获时间。财报追加版本、SDK 列和 PIT 日期不变。

同步持 M，网络期间不持 P 或排他 R。发布持 P／排他 R，业务数据、窗口资格、覆盖与全局 revision 在同一事务提交；无实际数据／资格变化不递增 revision。Research 跨查询读锁及修订后会话重建保持。只有真实发布争用封锁新计算；空库、历史缺口和来源错误不封站。Job／Agent owner 锁继续清理。

旧通用来源证据、动态表 delegate、变化数组、候选资源扫描、计算副本和四张退役元数据表已从新实现移除。未知旧目录交由管理员核对，后台不递归删除。MaintenanceRun 仅为部署记录保留。

旧库升级必须走 [一次性导出／恢复脚本](../../scripts/upgrade-minimal-sync.mjs) 与 [bootstrap](../../../../scripts/bootstrap.sh)：排空停服，导出受限恢复文件并备份，应用原样生成迁移，恢复并核对分红捕获时间／revision、重算覆盖，再启动 API。任何中途失败保留恢复文件和停服状态；重新部署沿用原文件。不能对旧库直接裸迁移后开放服务。具体命令见 [脚本索引](../../scripts/README.md)。

生产每两小时 :15 的 timer 沿用，oneshot 不设启动时限；正在运行时不叠加启动同一服务。ETF／指数对象来自 [下载名单](../market/downloads/README.md)，空名单不自动重置，移出停止请求且保留历史。完整设计见 [裁剪计划第 5 节](../../../../docs/design/system-simplification-plan.md#5-数据维护重新设计)。最小同步改造的构建、回归、隔离迁移及中英浏览器验收见裁剪计划第 28.4 节；数据集契约验收见第 29 节，来源选择与去除策略版本见第 30 节。

ETF 目录跳过待上市产品；退市名单代码仅补至有效退市日，缺日期时以代码级缺口报告并跳过，不阻断其他对象。旧无依赖待上市目录由人工 `data clean` 清理，详见 [ETF 维护设计](../../../../docs/design/etf-data-maintenance.md)。

## 数据集契约

来源协议参数和快照／分页方式见 [request-contract.ts](../market/providers/tushare/request-contract.ts)，字段映射与完成判断留在各领域。公共 `source.ts` 只执行声明的传输方式、映射和数值工具，`prepare.ts` 只分派。股票和 ETF 共用完整 OHLC 约束，日历序列验证由领域显式调用。

状态的 `completion` 区分 sessions／calendar／catalog／snapshot／reports／events。`verifiedThrough` 只用于连续序列；`checkedThrough` 表示检查过的范围或目录日期，不能冒充报表披露齐全或权重快照日。`maxObservedDate` 仍表示实际保存的数据日期。快照沿用过去实际公布日期，月中没有新权重不会生成未来快照。报告期只能在季度结束后检查。

本轮错误决定本轮 error；历史未解决缺口单独报告，已被新目录快照或升级修复撤销的尝试标为 superseded，不制造成功历史。来源已探明但不提供的指数早期范围标为 unavailable，不能作为消费者的有效价格证明。

同步只使用当前代码中的一套规则，不携带、保存或比较策略版本。日历或股票价格变更／失效时，同一发布事务撤销相应下游资格；目录仅按实际上市范围变化撤销，不因请求失败撤销历史。普通同步不做规则版本对账。

本次旧库升级由 [upgrade-sync-proofs.mjs](../../scripts/upgrade-sync-proofs.mjs) 在停服、备份后且 schema 迁移前处理：撤销股票日数据、名称、指数成分、财报、指标和分红的旧完成资格并清空连续覆盖，保留原始值、首次捕获时间、最大观察日及真实失败记录。更早协议的完成凭证整体撤销，避免遗漏依赖；当前日历、目录、ETF 和指数序列的有效凭证可保留。Prisma 生成的后续迁移删除旧列，之后升级脚本自动跳过；不新增版本号或转换标记表。失败保持停服，重新部署可继续；不能绕过预处理直接迁移旧库。重新校验按固定目标继续，来源不完整时保留缺口，覆盖可能暂时下降。

日历前瞻同时覆盖目标日期和实际捕获日期。未知指数来源起点通过一次有限、完整的来源历史查询确定，探测得到的目标之后数据不入库；请求截断或失败不会产生边界证明。已确认的目录和来源边界见 `scopes.ts`。入库映射仍规范证券代码；存量身份归并由人工 `data clean` 执行，日常同步不再扫描旧历史。

验收清单与升级说明见 [设计记录第 29 节](../../../../docs/design/system-simplification-plan.md#29-按数据集规则收敛维护流程)。

部署（包括首次部署）不执行 sync 或 clean，只安装定时任务。旧 schema 的必要搬移与凭证升级暂时保留，不能用可选人工清理替代；生产升级状态未核实前不删除兼容。退役来源清理从 sync 移至 `data clean`。市场范围清理共享入库边界规则，不增策略版本或通用修复框架。


股票入库和覆盖复用 `instruments/market-range.ts` 的日期判断，目录只同步 L/D/P 三种已上市或曾上市状态。有效上市／退市边界外不要求行情，入库前排除；同市场旧代码接续保留最早上市日，旧代码停用不能作为新代码退市日。新代码缺少前身目录时，上市日前的历史标为未知，不丢弃。

P 是暂停上市，不能按未上市处理，也不能用当前 P 推断过去哪天开始暂停。合法行情足以证明当日有交易，普通 `suspend_d` 记录或空时段不否定它；来源同时返回停牌与行情时保留诊断注记。未知范围不授予完整覆盖。G/UN 不请求、不进入日数据及分红范围；存量目录由 pending-stocks 核对历史与同步引用后人工清理，带上市日期等矛盾记录保留。

存量清理共用证券区间与已核实市场事实，但删除授权更保守：只有已核实的前身市场范围自动列为可清理，单凭当前目录越界仍留待核实。取消同步整轮上限不意味着运行完成就没有历史缺口，也不改变 `data clean` 的人工入口。


交易所来自 `stock_basic.exchange`（SSE/SZSE/BSE），迁移只增加可空列，旧行等待目录刷新，不按代码后缀回填。涨跌停先按股票目录确认身份，再使用 ETF 目录和权威 B 股编码范围排除非维护对象；`stk_limit.exchange` 只做一致性检查，不能单凭来源标签将 B 股纳入 A 股范围。未知身份不写 StkLimit 并记录缺口，真实目录冲突报错。B 股编码来源见 [深交所代码区间表](https://www.szse.cn/marketServices/technicalservice/doc/P020240510623040090566.pdf) 与 [上交所 B 股目录](https://www.sse.com.cn/assortment/stock/list/share/)。

历史每日预期范围由 L/D/P 的上市、退市、市场进入日期计算，不将当前 L 名单当历史快照。股票目录的退市日是摘牌生效日，可交易区间在此前结束；旧代码接续规则保持。`instruments/trading-interruptions.ts` 保留公告确认的历史区间，当日 suspend_d 仍校验响应格式与完整性，不增加每日历史目录接口。

股票和 ETF 信任成功且完整的来源响应：合法范围内无记录标为 `Source returned no ...`，不推断停牌，不补零、不生成价格。这类注记随窗口存入既有 DatasetSyncPartition.gaps 并输出到 CLI；窗口仍可 complete，注记不进入运行失败 gaps，也不计 pending。连续核验水位代表来源范围已检查，最大观察日仍来自实际记录；图表和 SDK 继续返回真实、可能稀疏的行。索引与日历仍使用各自完整性规则，请求失败、截断、格式错误、身份未知或目录冲突仍不能完成。

来源无记录不授权擦除已有合法值。完整核验的涨跌停回补在同一发布事务内仅删除该日期已确认范围外的旧限价；其他日期留给人工 market-range 清理。该人工清理只撤销实际受影响日期的 stock-limits 凭证，未知证券保留；日常同步不扫描历史全表。0/0 限价原样保存，回测不把上限 0 当作有效交易限制。

目录写入只返回业务日期变化，由 `dependencies.ts` 在同一事务撤销重叠凭证。新增股票从上市日起重查；更名、地区等变化以及目录请求失败不撤销过去行情。股票凭证按全市场单日保存，实际重查粒度是受影响交易日；ETF 按名单代码及相交日期处理，名单外目录更新不触发回补。已经失效的旧凭证不能直接恢复，仍需后续核验。运行缺口与错误包含数据集、对象、日期范围以及 historical/target 标记。

目录缓存仍按一天刷新，但旧行缺少有效 exchange 时提前重新获取该状态目录，避免 schema 升级后继续使用缺字段缓存；不引入版本号或部署同步。
