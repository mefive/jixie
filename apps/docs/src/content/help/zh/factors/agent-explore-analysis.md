# 让因子 Agent 运行探索分析

编辑自定义因子时，可以要求 Agent 用当前代码或一个明确候选运行探索分析。Agent 会先冻结研究卡和分析设置，再读取 Rank IC、费后多空、换手等摘要，用于解释和修正候选。

这项能力只适用于探索阶段，不能替用户启动或揭示正式保留段。

## 怎样提出要求

一条完整要求至少包含：

- 因子假设；
- 预期方向；
- 主要判断标准；
- 月频或周频；
- 开始和结束日期；
- 中性化方式。

例如：

> 假设盈利能力更稳定的公司后续收益更高。使用月频、2020-01-01 到 2024-12-31、市值加行业中性化，主要看 Rank IC 均值是否为正。先运行一次探索分析，再解释覆盖率、IC、换手和费后结果。

如果没有方向性假设，应明确说是“纯探索”。纯探索报告不能因为结果看起来不错就事后改写成预先假设。

## 系统会保存什么

Agent 启动分析时会创建一份真实的不可变因子报告，保存：

- 自定义因子或候选完整代码；
- 研究卡；
- 日期、频率和中性化；
- 股票池、缺失值、异常值和成本口径；
- 数据截止日和运行状态；
- 完成后的完整报告结果。

对话只读取紧凑摘要，但可以从右侧报告历史重新打开完整报告。取消对话后，已经创建的报告任务仍可能独立完成，不会留下半份结果。

## Agent 不能做什么

因子 Agent 不能：

- 越过已经封存的探索数据边界；
- 启动或揭示正式保留段；
- 把因子标记为最终通过；
- 自动部署策略；
- 把一次探索结果描述成未来有效。

同一轮通常只比较一到两个实质候选，避免围绕同一段探索样本机械调参。

## 分析完成后怎样检查

1. 从报告历史打开 Agent 创建的报告。
2. 核对代码快照和研究卡。
3. 检查共同样本、缺失值和数据截止日。
4. 阅读 Rank IC、分组收益、换手、费后收益和回撤。
5. 如果 Agent 同时给出新代码，确认屏幕报告对应的是哪个候选。
6. 需要继续研究时，先写下新变体理由，再运行新报告。

不要只复制 Agent 回复中的一个 IC 数字。完整报告中的样本、成本和稳定性决定这个数字是否有解释价值。

## 与手动“运行分析”的区别

两者使用同一套报告和研究纪律。区别只是启动入口：

- 手动运行由用户在页面填写研究卡并点击确认；
- Agent 运行由对话把候选、研究卡和设置一起提交，并在完成后读取摘要。

无论从哪里启动，历史报告都不会被后续代码覆盖。
