# 第一次完成量化研究

研究工作台把问题、公式、Python 计算、表格和图表放在同一份可复现文档中。你可以自己写 Python，也可以让
Research Agent 帮你生成和解释代码；不需要编写 SQL 或 TypeScript。

## 开始研究

1. 打开顶部“研究”。
2. 选择完整示例，或新建空白研究。
3. 在 Markdown Cell 写下问题、事前假设、公式、变量定义和限制。
4. 在 Python Cell 通过 `data.series()` 读取平台数据，用 pandas / SciPy / statsmodels 计算，并用 `charts.*`
   或 Matplotlib 画图。
5. 运行当前 Cell、受影响分支或干净运行全文；完整运行会保存不可变快照，供之后回看和封存。

如果成功封存的版本包含一个明确、由平台数据能力支持的时点信号，可以在快照中创建 Factor 草稿。系统会先让
LLM 判断研究能否转换，再用 Factor 编译器检查生成代码；不能转换时会说明原因。Factor 页面会保留来源快照、
提炼摘要和待验证项，并可回跳到原快照。这个操作只创建草稿，不会自动证明因子有效，也不会运行报告、揭示
Holdout 或发布 Factor。

如果研究已经明确标的或股票池、信号方向、调仓或进出场条件以及仓位规则，也可以从同一快照生成 Python
Strategy 草稿。草稿默认使用 `py-v1`，打开后会在 Strategy Lab 保留来源、摘要和待验证项。它不会自动运行
回测；需要先检查生成规则、设置回测区间、资金和成本，再由用户显式运行。只有预测关系而没有组合与交易规则的
研究会被要求先进入 Factor，而不是让 Strategy 绕过正式验证。

Factor 当前仍使用 TypeScript SDK/runtime；Python Factor 支持尚在 backlog。Research → Factor 暂时会生成
TypeScript 定义，Research → Strategy 则默认延续 Python。

Agent 可以补充统计方法和公式、修改 Markdown/Python Cell，并基于真实输出解释结果；它不能把未运行的代码说成
已经计算，也不能用文字替代代码与输出。缺少数据或方法时，系统会明确报告能力缺口。

## 研究一个股票池

也可以直接描述横截面条件，例如“找最新可得时点 PE TTM 小于 20、按总市值降序的 A 股”。结果会保存完整的 UniverseSpec，包括：

- 数据时点和历史指数成分时点；
- 上市天数、停牌和风险警示处理；
- 指标版本、单位、缺失值、过滤和排序；
- 数据 revision 与各资格阶段的样本数。

点击结果表中的对象会打开统一对象详情页。重新打开研究记录时，可以用同一份 Spec 确定性重跑。

> 统计关系和条件匹配都不是买卖建议。先确认变量定义、时间方向、样本范围和限制。
