# 将研究交给 Factor 或 Strategy

研究工作台用于自由探索；FactorReport 和回测工作台用于受约束的正式验证。交接入口只出现在成功的不可变完整运行上，不会把当前草稿或一次单 Cell 输出直接当成可发布结果。

## 先形成可复现快照

1. 检查 Markdown 中的问题、事前方向、日期、频率、对象或股票池和判断标准。
2. 点击“干净运行全文”。
3. 等待全部 Cell 成功。
4. 打开“完整运行历史”，选择本次记录。
5. 点击“封存为研究版本”，填写版本名、标签和备注。

封存只是给已有成功快照命名，不会重新计算。只读快照会保留源码、输出、依赖和环境摘要，并提示当前草稿是否已经变化。

![已封存研究版本的只读快照](/docs/images/help/zh/research/handoff-01.png)

## 生成 Factor 草稿

当快照包含一个明确、由平台数据能力支持的时点信号时：

1. 在封存版本中点击“生成 Factor 草稿”。
2. 等待系统提炼信号定义并生成 Python `py-v1` 代码。
3. 在因子研究页面逐行检查输入字段、方向、窗口、缺失值和股票池。
4. 核对来源卡片中的原研究版本、提炼摘要和待验证项。
5. 设置 FactorReport 范围，显式运行分析；需要发布时再选择与当前定义一致的批准报告。

研究中支持的股票池、日期、频率、过滤和事前方向可以成为建议参数，但不会自动运行报告、揭示 Holdout 或发布 Factor。

如果研究只有时间序列关系、没有可在每个决策时点计算的信号，系统可能拒绝转换。先回到文档明确输入和计算规则。

## 生成 Python Strategy 草稿

当快照还明确了标的或股票池、信号方向、调仓或进出场条件和仓位规则时：

1. 点击“生成 Python Strategy 草稿”。
2. 在回测工作台检查来源提示和 `py-v1` 代码。
3. 核对日期、初始资金、成本、标的和仓位规则。
4. 显式点击“运行回测”，再查看结果和日志。

只有预测关系、没有组合与交易规则时，应先进入 Factor，而不是让系统猜测交易动作。策略草稿不会自动运行，也不会自动部署到“今日信号”。

## 交接后仍要保留的边界

- 来源快照不会随着当前文档继续编辑而改变。
- Factor 或 Strategy 草稿是独立对象，后续修改不会反写研究快照。
- 探索图表和 Agent 解释不是正式证据；FactorReport、Holdout、成本、容量和回测仍要分别完成。
- 历史通过不保证未来收益，也不是买卖建议。
