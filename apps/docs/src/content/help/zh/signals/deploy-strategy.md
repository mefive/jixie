# 部署回测报告

部署将一份成功回测报告固定为独立运行实例。后续修改策略或再次回测，都不会改变已有部署。

## 选择报告并部署

1. 在回测工作台打开策略，在回测历史中选择准备部署的报告。历史报告也可以部署。
2. 查看这份报告的结果与报告信息，确认它是准备运行的版本。编辑器展示的当前草稿可能与历史报告不同。
3. 点击“部署上线”，成功后显示“暂停上线”。
4. 打开“今日信号”，核对报告来源、部署编号、部署日期和状态。点击报告来源可回到对应报告。

仅支持成功且有结果的 TypeScript 股票/ETF 报告，Python 与期货暂不支持。引用的 Factor 必须满足发布要求，且血缘与报告一致；缺少证据或因子变化时需重新回测，部署新报告。

## 报告、草稿与部署的关系

- 修改草稿不会改变报告或部署，也不会把已部署报告标成“旧版本”。
- 两份报告即使策略和参数完全相同，也可以各自部署、同时运行，各自记录信号和账户。
- 同一报告最多有一个运行中的部署，重复点击返回已有部署。
- 新报告上线不会自动暂停其他部署。需要停止哪个，就在“今日信号”选中该部署并点击“暂停部署”，或在 Lab 选择来源报告后点击“暂停上线”。
- 暂停后再次部署同一报告，会新建部署和账户，旧信号与账户继续保留。

## 常见问题

### 有尚未运行的修改，还能部署吗？

可以部署已经成功的报告。部署使用报告内的配置，与尚未运行的草稿无关。要部署修改后的内容，先运行回测并选择新报告。

### 为什么“部署上线”不可用？

需要选择成功的 TypeScript 回测报告，并等待报告加载完成。部署时还会检查股票/ETF 支持范围与 Factor 发布条件。

### 历史部署为什么显示“未关联报告”？

旧数据没有可靠保存来源报告。系统保留原有冻结配置与运行状态，不根据代码相同猜测来源。这类部署仍能查看、运行和暂停。

### 部署后能否删除策略？

有部署记录的策略不能删除，包括已暂停的部署。这样可以保留报告来源、信号和账户历史。

部署不会连接券商或自动下单，也不会保证每天产生交易指令。
