# 查看信号指令

信号生成完成后，先核对日期和模型权益，再阅读指令、模拟成交与实际执行。执行日收盘数据发布后，
系统会自动结算模拟账户；实际成交需要用户回填。

## 页面结果

下图是一条真实买入指令：

1. 策略名称、部署日期、代码版本和运行状态。
2. 手动生成入口。
3. 本次运行日志。
4. 信号日、执行日、模型权益和邮件通知。
5. 买卖指令表。
6. 参考价说明。

![今日信号的买入指令](/docs/images/help/zh/signals/signal-result-01.png)

## 先核对四项摘要

### 信号日

策略读取这个交易日的收盘数据。表格中的参考价也来自信号日。

### 执行日

信号日之后的下一个交易日。实际操作通常在执行日开盘后进行，但仍要遵守停牌、涨跌停和实际可成交状态。

### 模型权益

冻结策略按信号日数据运行后的模型账户权益。它用于把目标权重换算为股数，不是用户真实账户余额。

### 邮件通知

显示已发送、发送失败或未发送。通知状态和策略计算状态是两件事；邮件失败不等于信号计算失败。

## 三层账户对照

- 模型权益：冻结策略按历史数据重放得到的理论账户。
- 模拟权益：从同一持仓基线出发，按真实开盘、停牌、涨跌停、T+1、费用和滑点结算。
- 实际权益：只应用用户确认回填的成交；未执行不会被假定为成交。

执行率统计已执行笔数占已作决定笔数；平均不利偏差比较实际成交价与模拟成交价。买入价格更高、卖出
价格更低都记为不利偏差。

## 阅读与回填执行表

| 列 | 含义 |
| --- | --- |
| 标的 | 证券名称和代码 |
| 指令 | 买卖方向、模型股数和信号日参考价 |
| 模拟成交 | 次日是否可成交，以及模拟股数、开盘成交价或阻断原因 |
| 实际执行 | 用户回填的成交或未执行状态 |
| 回填 | 记录实际股数、价格、费用、原因和备注 |

概算金额用于估计指令规模，不包含执行日价格变化、实际滑点和全部费用。

## 参考价不是成交价

页面明确说明：

- 参考价是信号日不复权收盘价。
- 实际成交发生在执行日。
- 开盘价格可能与前一日收盘不同。
- 停牌、涨跌停、流动性和订单规模都可能影响成交。

因此不要把表格中的参考价直接记作真实成交价，也不要据此计算已经实现的收益。

## 买入和卖出代表什么

指令来自模型当前持仓与目标持仓的差额：

- 买入：模型需要增加该证券数量。
- 卖出：模型需要减少该证券数量。
- 今日无操作：全部目标变化不足以产生有效指令。

它不是对单只证券的研究推荐，而是冻结策略在指定数据和资金口径下的计算结果。

## 运行历史

结果下方会保留每个信号日的状态和指令数量：

1. 左侧当前部署的最新状态。
2. 当前运行的日期摘要。
3. 按信号日排列的历史。

![今日信号运行历史](/docs/images/help/zh/signals/signal-history-01.png)

点击任意历史行可打开当日执行表。“已回填 1 / 1”表示该日每条指令均已记录决定，不代表全部成交。

## 操作前检查

1. 策略名称和代码版本正确。
2. 信号日和执行日正确。
3. 模型权益与预期资金口径一致。
4. 标的代码、方向和股数合理。
5. 实际账户已有持仓与模型假设没有明显偏差。
6. 执行日确认证券可以交易。

## 常见问题

### 股数为什么是 100 的整数倍

A 股普通股票按整手处理。实际交易规则以证券类型和市场为准。

### 模型权益为什么与真实账户不同

模型从部署版本的初始资金和历史运行推演，不读取用户券商账户。需要用户自行处理真实账户差异。

### 表格出现指令是否表示已经下单

不是。只有用户把该行回填为“已执行”后，实际影子账户才会应用这笔成交；系统仍不会读取或操作券商账户。
