# 国债曲线到每日信号：证据、回测与部署

> 学习路径 · 预计 90～120 分钟 · 建议先完成一次 ETF 时间序列因子分析和一次回测。

这项练习串起完整的运行链路：**用当时可得的中国国债收益率曲线生成 Factor，检验它对国债 ETF 未来收益的
历史关系，把同一个冻结 Factor 放进策略回测，再部署并核对某个交易日的 Factor 输入和待执行指令。**

案例使用 `511010.SH` 5 年期国债 ETF，以及内置 Factor `cgb_yield_decline_20`。正分表示当时可得的 10 年期
国债收益率相对 20 个交易观察前下降。它符合“收益率下降时债券价格可能上升”的直觉，但直觉、系统成功运行和
策略证据合格是三件不同的事。

## 已实际跑通的固定案例

2026-08-25，我们用全新账户依次运行了假设探索、一次正式 Holdout、费后策略回测、部署和 2026-07-30
每日信号。运行使用真实产品 API、任务队列和浏览器界面；部署在验收结束后已暂停，策略也已清理，没有连接券商
或实际成交。

| 项目 | 固定设置 |
| --- | --- |
| Factor | `cgb_yield_decline_20`，10Y 国债收益率 20 日下降幅度 |
| 研究资产 | `511010.SH`、`511260.SH`、`511090.SH` |
| 预测目标 | 各 ETF 未来 20 个交易日复权总收益 |
| 探索区间 | 2018-01-01 至 2025-01-27 |
| 正式 Holdout | 2025-02-05 至 2026-07-30 |
| 主要标准 | 跨三只 ETF 的 Newey–West t 中位数 `> 1.96` |
| 策略规则 | `511010.SH` 分数大于 0 时持有 80%，否则空仓 |
| 回测设置 | 100 万元；2bp 滑点；冲击系数 0.1；截至 2026-07-30 |
| 信号日／计划执行日 | 2026-07-30／2026-07-31 |

| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 探索 | 5 年国债 ETF | 0.1779 | 2.044 | 59.05% | 0.38% | 0.17% |
| 探索 | 10 年国债 ETF | 0.1443 | 1.951 | 59.20% | 0.48% | 0.24% |

探索段有 3,749 条有效观测，t 中位数为 **1.951**，已经略低于事前 `> 1.96` 的门槛。正式 Holdout 有
1,029 条观测，t 中位数反转为 **-1.918**，三只 ETF 的方向命中率都低于 50%。因此研究门槛没有通过，
而且样本外方向与假设冲突。

### 回测与每日信号的真实结果

同一冻结 Factor 能被策略引擎正确引用，并不表示策略有效。固定规则的回测结果为：年化收益 -0.41%、累计收益
-3.36%、最大回撤 -7.67%、Sharpe -0.16、换手 7.68 倍、183 笔成交；费用 31,139.73 元，滑点损耗
110,790.23 元。

![国债曲线 Factor 策略的真实费后回测结果](/docs/images/help/zh/learning/cgb-signal-backtest-result.png)

在 2026-07-30，系统冻结的数据截止也是 2026-07-30，`511010.SH` 的决策分数为 1.1900。规则因此生成
5,400 份的“买入”计划，参考价 140.85 元，计划在下一交易日 2026-07-31 执行。它仍是模拟指令；“待结算”
和“待回填”明确表示没有真实成交记录。

![国债曲线策略在指定交易日生成的 Factor 输入和指令](/docs/images/help/zh/learning/cgb-signal-daily-result.png)

固定裁决是：**系统链路通过，研究与策略证据不通过，不应作为生产候选继续启用。** 这条路径保留失败，是为了
展示部署能力不能替代研究门槛。

## 学完以后

你应该能够：

1. 区分 Factor 证据报告、策略回测、部署快照和每日信号；
2. 核对国债曲线的来源、发布时间、下一交易日可得规则和 bp 单位；
3. 从报告到回测再到信号逐层核对 Factor key、代码 hash、输入和数据截止；
4. 处理任务的 `queued → running → done` 生命周期，而不是把排队误报成失败；
5. 在系统可以运行、但研究门槛或费后结果失败时停止生产部署。

## 第一步：先分清四层证据

这条路径每往下一层，回答的问题都不同：

| 层次 | 回答的问题 | 不能说明什么 |
| --- | --- | --- |
| Factor 报告 | 历史分数与未来收益是否有统计关系 | 实际交易收益 |
| 策略回测 | 明确仓位和成本后的历史路径怎样 | 未来仍会有效 |
| 部署快照 | 哪份代码和 Factor 依赖将被每日运行 | 今天一定有指令 |
| 每日信号 | 某日实际读取了什么数据、生成什么计划 | 券商已经成交 |

如果 Factor 研究失败，后面三层仍可能在工程上正常工作。本练习会运行它们来验收系统，但最终裁决不能因此改成通过。

## 第二步：冻结国债曲线假设

在“因子研究”的“因子库”中选择“国债10Y收益率20日下行”。Factor 定义为：

$$
S_t=100\times(y^{10Y}_{t-20}-y^{10Y}_t)
$$

`y` 的原始单位是百分比，乘以 100 后，`S` 使用 bp。`S_t>0` 表示收益率下降。平台使用财政部—中国国债
收益率曲线，并从发布后的下一上交所交易日才允许策略读取，不能在曲线公布前使用当天值。

打开“更多设置”，冻结三只期限不同的国债 ETF、20 日未来收益、2018-01-01 至页面当前探索段结束日，以及
Newey–West 自动滞后。运行前研究卡填写：

```text
假设：当可得的中国国债 10 年期收益率在过去 20 个交易观察中下降时，
      国债 ETF 未来 20 个交易日收益倾向更高。

逻辑：收益率下降通常对应债券价格上升，但 ETF 久期、票息、曲线形变、
      交易成本和发布时间差异都可能削弱关系。

预期方向：正向。
主要标准：跨三只 ETF 的 Newey–West t 中位数 > 1.96。

反证条件：正式 Holdout 未达到门槛、方向反转、命中率低于 50%，
          或费后策略没有保留可接受的结果。
```

`1.96` 是本练习事前指定的筛选线，不是任何时间序列 Factor 的通用认证标准。不能在看到 `1.951` 后把门槛
改成 `1.95`。

## 第三步：先读探索报告，不急着进入策略

运行后按顺序检查：

1. 输入是否只有 `rates.cgb.yield.10y`，窗口是否为 21 个观察；
2. 研究资产是否只有三只国债 ETF；
3. 数据截止是否等于探索段结束日；
4. 三只资产各自的有效观测、相关性、稳健 t 值和方向命中率；
5. 正分与负分状态的未来收益差，而不是只挑最高的一只 ETF；
6. 报告是否明确写着“信号证据报告，不是策略回测”。

本案例的两只较短久期 ETF 看起来较强，但 30 年 ETF 的 t 值只有 1.356，跨资产中位数又差 0.009 才达到门槛。
这属于门槛未通过，不是“约等于通过”。

## 第四步：只揭示一次正式 Holdout

从原始探索报告发起“验证保留段”。计算完成后先确认结果保持封存、任务日志没有泄露指标，再进行一次不可逆揭示。
记录实际开始、结束、代码 hash、首次揭示时间和预设门槛。

本案例 Holdout 不只是数值变弱，而是三只 ETF 的相关性和 t 值全部变成负数。可能原因包括利率周期改变、ETF
久期与曲线点不匹配、曲线其他期限形变、票息和持有收益、20 日重叠目标，或探索期偶然性。当前报告只能说关系没有
保持，不能从同一 Holdout 继续挑窗口寻找翻盘版本。

## 第五步：把冻结 Factor 放入策略回测

为了验收下游链路，建立以下 TypeScript 策略：

```ts
const bond = '511010.SH';

export default defineStrategy({
  name: '学习案例：国债曲线每日信号',
  watch: [bond],
  factors: ['cgb_yield_decline_20'],
  onBar(ctx) {
    const score = ctx.factor('cgb_yield_decline_20', bond);
    if (score != null && score > 0) {
      ctx.setHoldings({ [bond]: 0.8 });
    } else {
      ctx.setHoldings({});
    }
  },
});
```

运行后首先展开“本次回测使用的因子”，核对：

- key 是 `cgb_yield_decline_20`；
- 输入包含 `rates.cgb.yield.10y`；
- Factor ID、代码 hash 和回测结果一起冻结；
- 有 183 笔成交，说明规则确实执行，而不是一条空曲线；
- 费用和滑点均为非零。

年化收益和 Sharpe 为负，与 Holdout 的失败互相印证。不要把较小的最大回撤单独挑出来包装成成功。

## 第六步：部署只验证运行契约

只有在安全的测试环境中继续本步骤。点击“部署上线”后，部署快照应冻结：

1. 策略代码和设置；
2. Factor key、Factor ID 和代码 hash；
3. 曲线输入 `rates.cgb.yield.10y`；
4. 部署时间和当前状态。

运行指定信号日后，在“今日信号”检查信号日、计划执行日、模型权益、Factor 有效／观察数、均值和决策标的值。
2026-07-30 的分数 1.1900 只能证明系统按冻结定义得到正分；它不能推翻完整 Holdout 和回测。

页面出现“买入”时，还要区分：

- **指令**：模型准备在下一交易日采取的动作；
- **模拟成交**：系统模型用于后续记账的执行；
- **实际执行**：用户从券商回填的真实结果。

本案例截图中的“待结算／待回填”不是遗漏，而是防止把计划误写成成交。完成验收后暂停部署。

## 第七步：写出最终裁决

使用固定模板：

```text
研究结论：不支持进入生产候选。

证据：探索期 t 中位数 1.951，未达到事前 >1.96；正式 Holdout 为 -1.918，
三只 ETF 方向全部反转；固定规则费后年化 -0.41%、Sharpe -0.16。

工程结论：Factor 依赖、任务队列、回测、部署、指定日期运行和下一日指令均可追溯地完成。

行动：暂停测试部署，不把 2026-07-30 的单日买入计划视为投资建议；若提出新机制，
必须建立新的探索问题和未来未观察样本，不能复用这段 Holdout。
```

## 完成检查

- [ ] 能从 Factor 报告说出数据截止、有效观测和三只 ETF 的稳健 t 值；
- [ ] 没有把 `1.951` 四舍五入成“达到 `>1.96`”；
- [ ] 只揭示了一次正式 Holdout，并保留方向反转结果；
- [ ] 回测中 Factor key、曲线输入和代码 hash 可以追溯；
- [ ] 费用、滑点、换手和成交数都来自真实结果；
- [ ] 每日信号的数据截止不晚于信号日，执行日是下一交易日；
- [ ] 能区分指令、模拟成交和实际执行；
- [ ] 验收后暂停失败案例的部署。
