# 沪深 300 趋势策略：参数、成本与样本外

> 学习路径 · 预计 90～120 分钟 · 需要会运行一次回测；本练习使用 TypeScript，因为参数扫描当前只支持
> TypeScript 策略。

这项练习检验一个有限、可执行的问题：**当沪深 300 ETF（`510300.SH`）的收盘价高于过去若干交易日的简单
移动平均时持有，否则持有现金，这条规则在固定成本和样本切分下是否仍有可信证据？**

目标不是找到历史收益最高的均线，而是学会把一个直觉写成明确规则，再用可交易基线、相邻参数、成本、成交和
样本外结果主动寻找它的弱点。

## 已实际跑通的固定案例

2026-08-25，我们按下文原样运行了买入持有、120 日主规则、10 bp 滑点压力，以及 20／60／120 日的样本内外
扫描。固定数据截止为 2025-12-31，初始资金为 100 万元，基础滑点为 2 bp、冲击系数为 0.1；切分日为
2020-12-31。专用浏览器验收不仅等待页面出现，还断言每次回测、成本变化、扫描单元和持久化报告都完整。

固定主参数确实降低了全样本回撤，但年化收益明显低于同一 ETF 买入持有；10 bp 压力又把年化收益从 0.96%
降到 0.22%。20 日规则样本外转负，60 日与 120 日只有很薄的正收益。因而这次案例的裁决是**证据不足**，不是
“发现了稳健趋势策略”。下面的练习保留完整流程，让你复核这个不够漂亮但更诚实的结论。

## 学完以后

你应该能够：

1. 区分不可交易的沪深 300 指数与可交易代理 `510300.SH`；
2. 把信号日、成交日、仓位和现金状态写成没有歧义的规则；
3. 在看结果前固定主参数、敏感性参数、样本切分和反证条件；
4. 用买入持有基线、样本内／样本外、成交明细和成本压力共同审查策略；
5. 接受“否决”或“证据不足”，不把一次回测直接送去部署。

## 开始前先补齐前置知识

- 如果还没使用过工作台，先完成[第一次运行回测](/help/getting-started/first-backtest)。
- 先读[策略和回测](/help/basics/strategy-backtest)与[为什么回测不等于未来收益](/help/basics/backtest-limitations)。
- 不熟悉 ETF 与指数的区别时，先读[股票、ETF 和指数](/help/basics/stocks-etfs-indices)。
- 参数扫描当前不支持 Python 策略；本练习必须选择 TypeScript。

## 第一步：在看结果前冻结实验卡

先把下面内容保存到策略对话或自己的研究记录中，不要运行后再修改日期和通过标准：

```text
问题：2015-01-01 至 2025-12-31，510300.SH 的长期均线趋势规则能否在计入成本后，
      相对同一 ETF 的买入持有基线改善回撤或提供可接受的费后收益？

规则：当今日复权收盘价高于 N 日简单移动平均时，目标持仓为 95%；
      当价格小于或等于均线时退出并持有现金；今日收盘产生信号，下一交易日开盘成交。

事前主参数：N = 120。敏感性参数：20、60；它们只用于检查参数邻域，不用于事后挑冠军。
样本：2015-01-01 至 2025-12-31；2020-12-31 为样本内结束日，之后为样本外。
基线：同一只 510300.SH、同一资金、日期和成本下的 95% 买入持有。

主要证据：样本内／样本外费后收益、最大回撤、Sharpe、换手、交易数、费用与滑点。
成本压力：主参数在基础成本和更高滑点下各运行一次。

反证条件：若优势只出现在一个参数、样本外方向反转、回撤没有改善，或提高合理成本后优势消失，
          就不能把这条规则称为稳健候选。
结论边界：单一 ETF、单一市场、历史日线；不证明未来有效，不自动生成信号或部署。
```

主参数先固定为 120 日，是为了让“敏感性检查”和“寻找最优参数”分开。如果看完 20／60／120 日结果后改称其中
最好的一项为事前选择，这段样本已经参与了选择。

## 第二步：冻结对象和执行语义

| 项目 | 本练习的固定口径 | 容易犯的错误 |
| --- | --- | --- |
| 交易对象 | `510300.SH` 沪深 300 ETF | 把 `000300.SH` 指数点位当成可成交价格 |
| 信号价格 | 平台复权日收盘序列 | 用未复权价格跨分红或份额变化直接算均线 |
| 信号时点 | 当日收盘后判断 | 按当日收盘产生信号，却假设在同一收盘价成交 |
| 成交时点 | 下一交易日开盘，受停牌、涨跌停、整手和资金约束 | 忽略无法成交或取整后的真实数量 |
| 风险状态 | 95% ETF 或现金，不做空 | 把空仓误写成负向押注 |
| 基线 | 同一 ETF 的可交易买入持有 | 只与不可交易价格指数比较 |
| 成本 | ETF 佣金、滑点和冲击；没有股票印花税和过户费 | 把滑点设为 0 后称为可实现收益 |

工作台图上的沪深 300 基准仍有参考价值，但它是指数口径。公平的主要基线应使用同一 ETF，因为 ETF 还包含
基金费用、跟踪差异、交易单位和真实成交成本。空仓期间采用工作台的现金口径，不要把它解释成货币基金收益。

## 第三步：先建立可交易的买入持有基线

新建一个 TypeScript 策略，直接写入下面代码。把它保存为独立策略，不要稍后用趋势代码覆盖，这样两份结果仍可
分别复查。

```typescript
const code = '510300.SH';

export default defineStrategy({
  name: '沪深 300 ETF · 95% 买入持有基线',
  watch: [code],
  onBar(ctx) {
    const price = ctx.price(code);
    if (price != null && ctx.shares(code) === 0) {
      ctx.orderTargetPercent(code, 0.95);
    }
  },
});
```

启动参数固定为：

- 起始 `2015-01-01`，结束 `2025-12-31`；
- 资金 `100` 万元；
- 基础滑点和冲击系数采用当前合理的非零设置，并记录准确数值；
- 不因结果不理想而移动起止日期。

运行后先检查第一笔成交是否发生在数据可用后的下一交易日，再记录累计／年化收益、最大回撤、Sharpe、交易数、
费用和滑点。基线不是“无策略”，它是趋势规则必须证明值得增加复杂度的简单替代方案。

## 第四步：写出可扫描的趋势规则

另建一个 TypeScript 策略，使用同样的 ETF。`lookback` 是唯一可扫描参数；95% 仓位保持固定，避免同时改变信号和
仓位后无法解释差异。

```typescript
const code = '510300.SH';

export default defineStrategy({
  name: '沪深 300 ETF · 收盘价均线趋势',
  params: { lookback: 120 },
  watch: [code],
  onBar(ctx) {
    const price = ctx.price(code);
    const average = ctx.sma(code, ctx.params.lookback);
    if (price == null || average == null) return;

    const invested = ctx.shares(code) > 0;
    if (price > average && !invested) {
      ctx.orderTargetPercent(code, 0.95);
    } else if (price <= average && invested) {
      ctx.exit(code);
    }
  },
});
```

这段代码只在持仓状态切换时下单，不会为了每天维持精确 95% 而反复微调仓位。`ctx.sma` 只读取截至当前日已经
可用的复权历史；信号在当前收盘后形成，订单由引擎在下一交易日尝试成交。历史不足时 `average` 为 `null`，
策略不交易。

先用与基线完全相同的日期、资金和基础成本运行默认 120 日版本。此时只检查代码与成交是否符合规则，不根据这次
全样本结果决定把参数改成多少。

## 第五步：核对普通回测而不是只看收益

按以下顺序查看基线和 120 日趋势结果：

1. 日期、资金、成本和 ETF 代码是否一致；
2. 趋势策略是否有买入和退出，成交数是否为合理的偶数或接近偶数；
3. 第一笔买入是否在均线准备好且信号出现后的下一交易日；
4. 累计收益和年化收益是否以更深回撤、更多换手或更高成本换来；
5. 相对工作台指数基准的差异是否可能来自 ETF／指数口径，而不只是策略；
6. 净值领先是否集中在少数阶段，长时间空仓是否造成明显机会成本。

用一张固定表记录，而不是只截取最好看的指标：

| 版本 | 区间 | 年化收益 | 最大回撤 | Sharpe | 年换手 | 成交数 | 费用 | 滑点 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 买入持有 | 2015–2025 | […] | […] | […] | […] | […] | […] | […] |
| 120 日趋势 | 2015–2025 | […] | […] | […] | […] | […] | […] | […] |

普通回测结果会被后续运行覆盖。需要长期复查时，应保留两个独立策略，并把准确设置和指标写入研究记录；不要把
当前 `lastResult` 当成不可变报告。

## 第六步：用参数扫描检查邻域和样本外

打开趋势策略的“参数扫描”：

1. 选择参数 `lookback`；
2. 依次填写 `20, 60, 120`；
3. 开启“同时运行样本内／样本外”；
4. 切分日期填写 `2020-12-31`；
5. 再次确认代码、日期、资金和成本没有改变；
6. 启动扫描并等待三组结果全部完成。

阅读时先回到实验卡：**120 日是主参数，20／60 日是敏感性检查。** 不把三者按全样本 Sharpe 排名后改称第一名为
“策略”。重点回答：

- 三个参数在样本内和样本外是否大致同向；
- 120 日样本外的费后收益、回撤和 Sharpe 是否与事前预期相容；
- 较短参数是否因频繁穿越均线产生更高换手和成本；
- 是否只有一个孤立参数异常好，而相邻时间尺度完全不支持；
- 样本外改善是否只是少数行情阶段贡献。

扫描报告会冻结本次代码标识、配置、成本、数据截止和每组摘要，是本练习比普通 `lastResult` 更可靠的策略研究记录。
如果看过样本外后继续改规则，2021–2025 已不再是未见数据；下一轮必须另找尚未参与选择的验证区间。

## 第七步：做成本压力并抽查成交

回到主参数 120 日的普通回测，保持代码、日期和资金不变，运行两次：

1. **基础成本**：使用实验卡中记录的非零滑点和冲击系数；
2. **压力成本**：把基础滑点提高到至少 `10 bp`，或基础值的两倍（取更高者），冲击系数保持一致。

比较年化收益、最大回撤、费用、滑点和期末权益。成本提高不会改变历史信号，却会改变成交价和净收益；如果很小的
成本变化就让结论翻转，策略边际过薄。

随后打开交易明细，至少抽查：

- 买入都发生在价格上穿并处于空仓之后，卖出都发生在价格回到均线下方之后；
- 信号日与成交日相差一个交易日，而不是同收盘成交；
- 没有每天为了维持 95% 目标而产生碎片化交易；
- ETF 成交没有股票印花税和过户费，但佣金、滑点仍为非负；
- 横盘阶段是否连续买卖并形成“来回打脸”的成本集中期。

若代码意图和成交记录不一致，先否决本次运行并修代码。指标再好也不能弥补执行规则错误。

## 怎样写结论

在最终记录中使用下面结构，并替换方括号中的真实结果：

```text
本练习事前固定 120 日为主参数，20／60 日只作敏感性检查；样本内截至 2020-12-31，
2021-01 至 2025-12 为首次样本外。

相对同一 510300.SH 买入持有基线，120 日趋势在全样本的年化收益／最大回撤为 […]／[…]，
基线为 […]／[…]。样本外的费后收益、最大回撤、Sharpe 和成交数为 […]。
20／60／120 日结果表现为 [大致同向／高度敏感／互相冲突]。

基础成本下费用与滑点为 […]；压力成本下净结果变化为 […]。成交抽查 [符合／不符合] 下一开盘执行规则。

因此证据 [支持进入下一轮研究／不足／否决]。即使支持，也只代表单一 ETF 历史日线上的候选规则，
尚未验证其他市场、其他时期、参数选择次数、现金收益、容量和真实执行，不进入部署。
```

趋势策略收益低于买入持有但回撤更浅，不一定自动失败；它说明收益与风险之间存在取舍。反过来，收益略高但回撤、
换手和成本都更差，也不能只凭一个 Sharpe 宣布成功。

## 完成检查

- [ ] 在运行前写明交易对象、规则、主参数、敏感性参数、样本切分和反证条件；
- [ ] 买入持有与趋势策略使用两个独立草稿和完全相同的日期、资金、ETF 与基础成本；
- [ ] 趋势信号只使用当时可得的复权历史，并由下一交易日开盘执行；
- [ ] 参数扫描固定 120 日为主参数，20／60 日只作敏感性检查；
- [ ] 同时记录样本内和首次样本外结果，不在揭示后继续称其为样本外；
- [ ] 查看成交、换手、费用与滑点，并完成一次更高成本压力运行；
- [ ] 结论明确写为支持、证据不足或否决，不自动部署；
- [ ] 保留本次参数扫描报告，并记录普通回测可被覆盖的限制。

全部完成后，你得到的是一条经过初步审查的策略研究记录，而不是“发现了一个赚钱策略”。
