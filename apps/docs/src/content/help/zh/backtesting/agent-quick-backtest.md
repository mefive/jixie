# 让策略 Agent 先做快捷回测

修改策略时，可以在对话中要求 Agent 先运行一次受限的快捷回测，再根据摘要解释候选代码。快捷回测用于减少明显无效的修改，不是工作台中的正式回测结果。

## 适合什么时候使用

- 检查修改后的代码能否正常运行；
- 比较一到两个实质不同的候选规则；
- 查看收益、回撤、Sharpe、成交和成本的紧凑摘要；
- 在把候选代码放进正式结果前发现零成交、日期不合适或规则方向错误。

不要用它连续尝试大量参数并只保留最好的一次。那会把同一段历史数据当作反复调参的答案。

## 怎样提出要求

在已经保存的策略中，可以写：

> 把月度买入数量改为 200 股。先用当前日期、资金和成本做一次快捷回测，说明与原规则最重要的差异，再给我完整代码。

需要指定范围时，应同时写清日期和资金，例如：

> 用 2022-01-01 到 2024-12-31、100 万元资金快捷试算。只检查这一个候选，不要继续搜索参数。

Agent 是否需要运行，由问题和已有证据决定。纯解释问题不必每次都触发计算。

## 运行过程中会发生什么

1. Agent 冻结本次候选代码和试算参数。
2. 系统在隔离进程中运行 A 股回测规则。
3. 对话显示工具正在运行和完成状态。
4. Agent 读取紧凑指标摘要并解释结果。
5. 如果需要修改代码，回复中仍会给出完整候选代码。

刷新页面后，可以恢复仍在进行的 Agent 对话任务。取消对话任务会终止尚未完成的快捷回测。

## 快捷回测不会做什么

快捷回测不会：

- 保存候选代码为策略正式配置；
- 覆盖工作台“结果概览”中的上一次正式结果；
- 生成完整净值图和交易明细；
- 部署上线；
- 生成今日信号或订单。

因此，对话中出现一个收益数字，不表示右侧工作台结果已经更新。

## 最后仍要运行正式回测

Agent 返回后按以下顺序操作：

1. 阅读它对快捷结果的说明和限制。
2. 核对中间编辑器中的完整代码。
3. 检查日期、资金和成本。
4. 点击“运行回测”。
5. 在正式结果中检查净值、回撤、交易明细、日志和成本。
6. 只有正式回测完成后，再考虑参数扫描或部署上线。

快捷结果和正式结果不一致时，以正式工作台中保存的代码、参数和结果为准，并核对两次运行是否使用了相同范围。

## 常见问题

### Agent 说候选表现更好，是否可以直接上线

不可以。快捷试算只是一段样本中的候选检查，没有完成正式结果核对、样本外验证和部署冻结。

### 为什么没有净值图和逐笔交易

对话只接收紧凑指标，避免把完整大结果塞进对话。需要图表和交易明细时运行正式回测。

### 可以让 Agent 自动比较几十组参数吗

不建议，也不是快捷回测的用途。多组数值、仓位方案和资金规模应使用“扫描实验”，并保留所有组合结果。
