# 运行回测和查看日志

设置完成后，点击“运行回测”。运行期间不要重复提交同一个策略，先通过页面状态和日志判断进度。

## 开始运行

运行前依次检查：

1. 当前打开的是正确策略。
2. 代码中的证券、方向、数量和频率正确。
3. 顶部显示的日期和资金正确。
4. 启动参数中的成本设置正确。
5. 点击“运行回测”一次。

## 运行中的页面

下图表示任务已经提交：

1. “运行回测”按钮进入运行状态，不能重复点击。
2. 结果区域显示“回测计算中”。
3. 日志区域开始显示启动和处理进度。

![回测运行状态、结果提示和实时日志](/docs/images/help/zh/backtesting/run-logs-01.png)

回测时间取决于日期长度、证券数量、策略计算量和数据规模。页面暂时没有指标不等于运行失败。

## 查看日志

日志包含两类内容：

- **系统进度**：启动、读取数据、完成或失败等状态。
- **策略输出**：代码中通过 `console.log` 写出的内容。

日志适合确认规则是否在预期日期触发。例如，月度策略可以输出调仓日期，但不应为了调试输出每一个交易日的大量重复内容。

## 运行完成

出现以下内容时，说明回测已经完成：

- “结果概览”出现指标。
- 净值或回撤图可以显示。
- 有成交时出现“交易明细（数量 笔）”。
- 日志最后出现完成信息。

完成后，结果会与当前策略一起保存。以后从“历史”重新打开策略时，可以查看上一次完成的结果。

## 刷新或重新打开

运行中刷新页面或重新打开当前策略时，页面会尝试恢复正在进行的任务。恢复后仍应检查日志和最终状态，不要因为短暂无显示就再次提交。

如果页面长时间停留在运行状态：

1. 查看日志是否仍在增加。
2. 等待当前任务结束。
3. 刷新后重新打开同一策略。
4. 仍然没有变化时，记录策略名称、日期范围和日志最后一行。

## 运行失败

失败时不要使用页面上之前留下的结果来评价本次修改。先查看错误信息和日志，常见原因包括：

- 代码无法编译。
- 使用了没有数据的证券或日期。
- 资金或参数不符合要求。
- 策略执行时间过长。

修改后再次运行，并确认新结果对应新的日期、资金和代码。
