# 用户使用手册建设计划

> 2026-07-28 制定。本文档用于规划面向产品使用者的使用手册，不是开发文档。

## 1. 目标

在产品前端提供一套完整的中文使用手册，让没有量化交易经验的用户也能：

1. 知道产品可以做什么、不能做什么。
2. 看懂页面上的主要数据和指标。
3. 按照明确步骤完成选股、查看股票、回测、因子分析、查看市场与估值、部署策略和查看今日信号。
4. 理解回测结果的限制，不把历史结果当作未来收益承诺。
5. 遇到常见问题时能够自行检查和处理。

手册以产品当前页面为准。只使用页面上真实存在的名称、按钮、输入项和结果，不介绍内部架构、接口、数据库或开发命令。

## 2. 当前文档现状

- `/docs/sdk` 是策略 SDK 参考页，由结构化的 SDK 定义生成，不是 Markdown 使用手册。
- 原 `/learn` 策略入门教程已经下线；旧地址统一跳转到 `/docs/help`。
- 前端已有 CommonMark/GFM Markdown 渲染组件，但目前主要用于对话内容，缺少文档目录、页面路由、图片规范和文档专用样式。
- `apps/web/acceptance/` 已有大量 E2E 验收截图，可以帮助核对页面，但不能直接视为最终手册截图。手册截图需要重新按教学步骤拍摄并编号标注。

现有 SDK 参考页继续保留。新的使用手册与 SDK 参考页分开：

- 使用手册：告诉普通用户如何使用产品。
- SDK 参考：供需要直接编写策略代码的用户查询方法和字段。

## 3. 编写原则

### 3.1 使用页面原文

步骤中出现的名称必须和页面一致，例如：

- “回测工作台”
- “运行回测”
- “交易明细”
- “选股看图”
- “保存筛选”
- “因子研究”
- “运行分析”
- “部署上线”
- “今日信号”

页面上没有出现的名称，不得自行创造后再要求用户寻找。

### 3.2 一步只做一件事

操作步骤使用连续编号。每一步必须写清：

1. 当前位于哪个页面或区域。
2. 点击、输入或选择什么。
3. 具体填写什么内容。
4. 完成后页面会出现什么。
5. 如何判断操作成功。

涉及等待的步骤要写明等待对象，例如“等待净值曲线和指标出现”，不能只写“等待完成”。

### 3.3 先操作，再解释必要概念

用户第一次完成任务时，只介绍完成该任务必须知道的概念。更完整的解释链接到“量化交易基础”。

例如：

- 第一次运行回测前，解释回测区间、初始资金和基础滑点。
- 第一次查看结果时，解释累计收益、年化收益和最大回撤。
- 第一次使用因子研究时，再解释因子、分组收益和 Rank IC。

不在第一篇文章里一次讲完所有量化知识。

### 3.4 使用直接、普通的语言

文档不使用宣传语，也不使用为了显得专业而创造的说法。

避免使用：

- 赋能
- 一站式
- 智能洞察
- 心智模型
- 探索之旅
- 轻松驾驭
- 强大能力
- 无缝体验

可以直接写：

- “在起始日期中选择回测开始日期。”
- “点击‘运行回测’。”
- “最大回撤表示回测期间从阶段高点到之后低点的最大跌幅。”

### 3.5 不隐瞒限制

相关页面必须明确说明：

- 回测结果来自历史数据，不代表未来收益。
- 参数反复调整可能造成过度拟合。
- 手续费、滑点和市场冲击会影响结果。
- 涨跌停、停牌和 T+1 会导致订单不能按预期成交。
- 今日信号是策略计算结果，不是收益保证或个别证券推荐。
- 数据更新日期决定用户当前能看到的最新范围。

### 4.9 常见问题

常见问题从真实操作和 E2E 过程中收集，不预先编造大量问题。第一版至少覆盖：

- 页面没有最新数据
- 查询没有结果
- 回测长时间没有完成
- 策略修改后结果没有变化
- 回测没有成交
- 指标显示为空
- 因子分析样本不足
- 当前报告提示已过期
- 部署后没有产生买卖指令
- 登录验证码或邀请码问题

## 5. 前端文档实现

### 5.1 内容格式

使用标准 Markdown 文件保存正文，图片使用标准 Markdown 图片语法。正文不写在 React 组件中。

建议目录：

```text
apps/docs/src/content/help/
├── zh/
│   ├── index.md
│   ├── getting-started/
│   ├── basics/
│   ├── screen/
│   ├── stock/
│   ├── lab/
│   ├── factors/
│   ├── market/
│   ├── valuation/
│   ├── signals/
│   └── faq/
└── en/
```

中文内容稳定后再逐篇提供英文版本。目录和加载方式从一开始支持按当前语言选择内容，不能把中英文混写在同一个 Markdown 文件中。

### 5.2 页面功能

第一版需要：

- 使用帮助首页
- 左侧章节目录
- 正文
- 当前文章目录
- 标题锚点
- 上一篇和下一篇
- 产品页面与帮助文章之间的链接
- 图片放大查看
- 窄屏显示
- 中文和英文内容选择

第一版不需要：

- 后台编辑器
- 在线发布流程
- 评论
- 阅读进度
- 推荐算法

全文搜索在文章数量和内容稳定后再决定是否加入。

### 5.3 与现有页面的关系

- 新的使用手册使用独立入口 `/docs/help`。
- `/docs/sdk` 保持为策略 SDK 参考。
- `/learn` 的内容经过页面核对后迁入使用手册，不直接复制旧文案。
- 回测工作台中的“第一次用?看入门教程”改为指向新的对应文章。
- 各主要页面在合适位置提供“使用帮助”入口，直接打开该页面对应章节。

## 6. 截图计划

### 6.1 截图来源

所有截图必须来自真实运行的前端页面。通过 Playwright E2E：

1. 启动测试所需的 API 和 Web。
2. 使用固定测试账号和固定数据。
3. 按文档步骤完成操作。
4. 等待页面数据、动画和图表稳定。
5. 隐藏或替换邮箱等个人信息。
6. 保存原始截图。
7. 生成带编号标注的文档截图。
8. 结束后关闭测试服务。

现有 E2E 脚本用于功能验收。文档截图应使用单独的截图脚本或明确分组，避免验收截图名称和文档图片互相覆盖。

### 6.2 截图标注

截图使用数字标记，并与截图下面的步骤一一对应：

- `1` 表示第一步点击的位置。
- `2` 表示第二步填写或选择的位置。
- `3` 表示操作完成后需要查看的结果。

截图中只放简短编号和必要边框，不在图片里堆放大段说明。详细说明写在图片下面，便于修改和翻译。

标记不能遮挡：

- 按钮原文
- 输入内容
- 数据日期
- 关键指标
- 错误提示

### 6.3 截图规范

- 固定桌面视口和设备缩放比例。
- 统一使用中文界面拍摄第一版。
- 一个截图只说明一个主要动作或结果。
- 页面过长时截取相关区域，不强行缩小整页。
- 文件名使用文章和步骤，例如 `lab-run-01-config.png`。
- 图片替代文字写明页面和动作，例如“回测工作台中的起始日期、结束日期和资金设置”。
- 不使用包含真实用户邮箱、策略名称或其他私人数据的截图。
- 图表截图要等待 ECharts 完成绘制。

### 6.4 截图更新

文档截图脚本使用稳定的可访问名称或具名 class 定位页面元素。页面按钮、字段或主要布局变化时：

1. E2E 截图检查应能发现变化。
2. 重新执行相关操作。
3. 更新对应图片和文字。
4. 不相关章节不重新拍摄。

## 7. 实施阶段

### 阶段 A：页面和功能清点

目标：得到准确的用户功能清单。

工作：

1. 逐个打开顶部导航中的页面。
2. 记录页面上真实可见的区域、按钮、输入项、提示和结果。
3. 运行现有 E2E，核对正常路径和异常路径。
4. 建立“页面功能—文章—截图—E2E”的对应表。
5. 标记旧 `/learn` 中已经过时或与当前页面不一致的内容。

交付：

- 功能清单
- 文档目录确认稿
- 截图清单
- 旧教程处理清单

### 阶段 B：Markdown 文档页面

目标：让前端可以稳定展示多篇 Markdown 使用手册。

工作：

1. 建立 `/docs/help` 页面和文档目录。
2. 加载 Markdown 文件。
3. 增加文档专用样式。
4. 支持标题锚点、文章导航、图片和内部链接。
5. 支持中文和英文目录。
6. 增加构建检查，避免失效链接和缺失图片。

交付：

- 可访问的空文档框架
- 一篇示例文章
- 桌面和窄屏验收截图

### 阶段 C：开始使用和基础知识

目标：让新用户完成第一次选股和第一次回测。

工作：

1. 编写“产品可以做什么”。
2. 编写登录、导航、第一次选股和第一次回测。
3. 编写完成这些任务需要的第一批基础知识。
4. 运行对应 E2E 并制作标注截图。

验收：

- 一名不了解项目的用户可以只看文档完成第一次选股和回测。
- 用户能够指出回测结果为什么不代表未来收益。

### 阶段 D：选股看图和股票详情

目标：覆盖选股、保存筛选、历史会话和股票图表。

工作：

1. 覆盖选股页面的主要操作和异常情况。
2. 覆盖 K 线、复权、PE 和成交量。
3. 补充估值和行情基础知识。
4. 运行对应 E2E 并制作标注截图。

### 阶段 E：回测工作台

目标：完整覆盖从创建策略到阅读结果。

工作：

1. 覆盖新建、生成、编辑、参数设置和运行。
2. 覆盖日志、净值、回撤、指标和交易明细。
3. 覆盖参数扫描、ETF、股指期货和混合策略。
4. 补充回测限制、成本和交易制度。
5. 运行对应 E2E 并制作标注截图。

### 阶段 F：因子研究

目标：让没有因子研究经验的用户能够正确运行和阅读一份报告。

工作：

1. 先完成预设因子的使用说明。
2. 再完成自定义因子和策略标识。
3. 解释分组收益、Rank IC、中性化、换手、相关性和样本外结果。
4. 覆盖历史报告和报告过期提示。
5. 运行对应 E2E 并制作标注截图。

### 阶段 G：市场、估值和今日信号

目标：覆盖剩余顶部导航和策略部署后的使用过程。

工作：

1. 编写市场与指数估值说明。
2. 编写百分位的正确理解方式。
3. 编写部署上线、生成信号、查看历史和暂停上线。
4. 解释信号日、执行日、参考价和无操作。
5. 运行对应 E2E 并制作标注截图。

### 阶段 H：整体验收

目标：确保整套手册可以独立使用并能继续维护。

工作：

1. 从新账号开始按文档完整操作。
2. 检查每个页面名称、按钮名称和截图。
3. 检查所有文章链接、标题锚点和图片。
4. 检查桌面和窄屏显示。
5. 检查中文文字是否直接、准确、无宣传语。
6. 补充真实遇到的常见问题。
7. 建立功能变更时同步更新文档的检查项。

## 8. 文章模板

每篇操作文章使用统一结构：

```markdown
# 文章标题

用一两句话说明完成后能得到什么。

## 开始前

- 需要的数据或已有操作
- 适用范围

## 操作步骤

1. 打开……
2. 点击……
3. 输入……

![截图替代文字](...)

操作完成后，页面会显示……

## 如何查看结果

说明应该看哪里，以及正常结果是什么。

## 需要知道

只解释与本操作直接相关的概念和限制。

## 常见问题

记录真实发生过的问题和处理方式。

## 相关内容

- 上一步
- 下一步
- 对应基础知识
```

## 9. 验收标准

一篇文章只有同时满足以下条件才算完成：

1. 所有步骤都在当前产品中实际执行过。
2. 按钮、字段和页面名称与中文界面一致。
3. 每个关键动作都有对应截图或明确说明截图不必要的原因。
4. 截图来自 E2E 操作，没有私人数据。
5. 用户能根据文章判断操作是否成功。
6. 专有名词第一次出现时有解释或链接。
7. 风险和限制没有省略。
8. Markdown、图片、内部链接和标题锚点正常。
9. 桌面和窄屏页面均可阅读。
10. 文章不包含内部实现和自造宣传用语。

整套第一版只有在顶部导航中的主要页面全部覆盖后才算完成。

## 10. 执行顺序

严格按以下顺序推进：

1. 先完成阶段 A 的功能清点和截图清单。
2. 用户确认目录和写作深度。
3. 再实现阶段 B 的 Markdown 文档页面。
