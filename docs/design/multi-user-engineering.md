# 多用户工程 V1

> 状态：2026-08-12 完成。本文是原 `ROADMAP.md` 4.5 的完成边界与验收真相源；当前归入已完成基础 D。

## 1. 目标

现有认证、Session 和绝大多数业务查询已经按 `userId` 隔离，但 CPU 密集任务仍由请求现场直接创建
worker，不限制全局并发；策略和因子也只能由所有者看到。V1 补齐两条多用户边界：

1. 所有正式长任务进入同一个持久、公平、有界的队列；
2. 策略和完成验证的因子可以由所有者选择公开，其他用户只能读取并复制为自己的私有资产。

## 2. 任务队列

### 2.1 调度模型

- `Job.status` 增加 `queued`，任务输入冻结在 `Job.payload`；`queuedAt / startedAt / finishedAt`
  记录排队和执行生命周期。
- 默认全局并发槽位为 2、每用户最多占 1 个槽位，可用环境变量调整。调度器按创建时间扫描队列，
  跳过已经占满个人槽位的用户，因此一个用户提交很多任务不会饿死其他用户。
- backtest、factor、strategy-scan、signal 四类正式 Job 共用队列。每个槽位仍启动一个短生命周期
  worker/子进程；不复用装载过用户代码的 isolate，确保内存和沙箱状态在任务结束后彻底释放。
- Job 创建和业务快照仍在同一数据库事务内；事务提交后只唤醒调度器。HTTP 返回 `jobId`，前端把
  `queued` 与 `running` 都视为进行中，并展示排队位置。

### 2.2 重启与维护

- API 重启时，已经在执行的 `running` Job 无法从计算中点恢复，按既有规则标成 `stale`；尚未启动的
  `queued` Job 保留并从冻结 payload 自动恢复。
- 部署/维护 Gate 同时等待 `queued` 和 `running`，避免服务停止时留下刚排队但尚未启动的任务。
- Job 的读取、恢复、日志和队列位置始终按所有者 `userId` 查询；其他用户拿到 ID 仍返回 404。

## 3. 公开资产

### 3.1 可见性与权限

- `Strategy`、`Factor`、`FactorComposite` 增加 `visibility = private | public`，默认 `private`。
- 只有所有者能切换可见性。公开不会改变所有权；更新、归档、删除、运行、部署和报告历史仍只属于
  所有者。
- 公共库只返回展示和复制所需的快照，不返回 Agent 对话、私有报告历史、部署、信号或账户数据。

### 3.2 发布约束与复制

- 策略公开前必须是自包含代码，不得引用所有者的自定义 Factor key。其他用户复制时只复制名称和
  `BacktestConfig`，新行默认私有、无历史结果、无对话。
- 因子只有 `published` 的不可变 Factor（以及已发布 Panel Composite）可以公开。其他用户复制后得到
  新的私有 `draft`，使用自己的唯一 key；不会直接执行或修改原资产。
- 公共库显示作者名称（无名称时使用脱敏邮箱前缀），不暴露完整邮箱。

## 4. 完成定义

1. 两个用户并发提交任务时，全局/每用户槽位限制和公平顺序有确定性测试；queued Job 在模拟重启后
   会恢复，running Job 仍正确 stale。
2. 四类正式 Job 都不再从 HTTP 请求现场绕过队列直接启动。
3. 外用户无法读取、修改、删除、运行或部署私有资产；公开资产只能读取公共快照和复制。
4. 策略依赖私有 Factor 时不能公开；复制出的策略/因子默认私有且没有原作者的对话、报告或运行结果。
5. API 回归测试覆盖跨用户私有资源隔离、公共资源读取和私有副本；中英文桌面与窄屏浏览器验收覆盖
   公共库入口、展示和响应式布局。
