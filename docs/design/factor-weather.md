# 因子气象设计

> 状态：已实现。因子气象是独立于因子研究报告的月频监测模块，不复用或修改不可变的
> `FactorReport`。

## 1. 产品定位

因子研究回答“这个定义在某个固定样本和方法下是否成立”，因子气象回答“已认可的因子最近表现怎样”。
页面采用卡片墙：每个被钉住的因子是一张卡片，横向时间条展示逐月强弱，用户可拖动并选择任意历史月份。

卡片不是实时选股器，也不在页面请求中计算。页面只读取离线月度观测，因此切换月份和浏览历史不会触发
全市场运算。

## 2. 固定方法口径

所有卡片使用同一套版本化方法，才可以横向比较：

- 频率：月频，月末形成组合并调仓，持有到下一月末；
- 展示范围：只写入已经结束的完整月份，不展示本月半成品；
- 中性化：行业加市值；
- 分组：十分位，组内等权；
- 样本规则：上市满 365 天，剔除流动性最低 25%，排除风险警示和待退市标的；
- 收益：同时保留原始 Rank IC、最高/最低组收益、费前和费后多空收益；
- 成本：双边佣金、卖出印花税和双边滑点沿用因子分析 V3 默认口径。

方法对象经 canonical JSON 后计算哈希，保存在 `FactorWeatherPin.methodologyHash`。代码升级若改变方法，
下一次刷新会删除该卡片旧点并按新口径全历史回填，不允许一张卡片混合两种方法。

## 3. 因子版本与方向

预置因子由仓库定义固定预期方向。自定义因子只有在已经定稿并分配稳定 `strategyKey` 后才能钉住，首次
钉住时必须选择“高值优先”或“低值优先”。方向只用于把卡片颜色、收益和滚动 IC 对齐到“符合预期为正”，
原始 IC 和原始收益不会被改写。

钉住时冻结 `factorCode`、代码哈希、名称和方向。被钉住的自定义因子不能修改代码或删除；需要迭代时，
先复制为一个新因子版本，再把新版本钉成另一张卡片。这样历史时间序列始终对应同一份可复现定义。

## 4. 计算和更新

首次钉住后，API 启动独立 worker，从 2015 年或实际最早行情日开始回填到最近一个完整月末。worker 复用
因子分析引擎，但只把逐月聚合结果写入 `FactorWeatherPoint`，不保存逐股暴露，也不创建研究报告。

之后有两种更新路径：

1. 用户在失败卡片上手动重试；
2. `jixie-maintenance-weekly.timer` 顺序刷新所有卡片，只增算尚未覆盖的完整月份。

增量计算会从已完成月份之前一个月开始，为窗口和前一期换手提供上下文，但只写入新的月份。计算中的
卡片不能取消钉住；生产维护在修改原始市场数据前也会等待在途因子气象 worker 结束，避免读写竞态。

部署只需要执行 `scripts/bootstrap.sh`。Prisma migration 会创建两张表；无需单独同步 Tushare 数据，
已有行情库上的卡片在钉住后自行回填。空库仍先按正常 bootstrap 流程完成行情初始化。

## 5. 卡片指标语义

- 选中月：该期方向对齐后的费后多空收益；
- 近 3 月 / 近 12 月：截至选中月的费后多空复合收益，不是简单相加；
- 12 月均值 IC：截至选中月最多 12 期 Rank IC 的方向对齐均值；
- 详情：保留该期原始 Rank IC、样本覆盖率、最高组换手和样本数；
- 时间条：红色表示符合预期方向，绿色表示背离预期方向，颜色深浅由当月费后多空收益幅度决定。

这些观测用于发现因子是否处于顺风、逆风、失效或恢复阶段，不直接等价于买卖建议。尤其单月颜色不应
替代完整研究报告中的经济逻辑、多重检验、保留段和成本评估。
