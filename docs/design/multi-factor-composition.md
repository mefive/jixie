# 多因子线性合成

> 2026-07-31 制定，对应 `ROADMAP.md` 3.3。目标是在因子页把已验证、低相关的单因子组成一个新的研究对象，并让组合沿用单因子的不可变报告、研究卡、explore/holdout、股票池、中性化和费后管道。

## V1 范围

- 选择 2–5 个预置或自定义因子。
- 每个成分声明方向：`positive` 保留原值，`negative` 取反。方向在运行前冻结，不能看到组合结果后回填。
- 每个调仓日先取所有成分均有值的股票交集，再分别做 `rank` 或 `zscore` 截面标准化，最后等权平均。
- 组合输出视为一个因子，进入现有 `analyzeFactor` 管道；股票池过滤、异常值、中性化、分层、IC、衰减、换手、费后和 holdout 不享受任何特权。
- 组合只存在于因子研究页，不进入策略引擎。策略生产代码仍显式写自己的因子与权重，避免研究工具悄悄决定投资风格。

## 为什么 V1 只有等权

等权是复杂组合的强制基线。若直接用当前 explore 全样本 IC 定权，再在同一段样本评估组合，会把训练和评估混在一起。后续 IC 加权只能采用以下一种可审计来源：

1. 绑定每个成分在组合研究开始前已经存在的冻结报告，权重与报告 ID 一起进入组合定义；或
2. 每个调仓期只用此前数据计算滞后 / 扩展窗口 IC。

在等权组合完成一次性 holdout 并证明有价值前，不建设风险优化、因子择时或 ML。

## 版本化输入

新增 `FactorAnalysisSpecV4`，在 V3 方法论参数上冻结：

- 组合名称；
- 标准化方式 `rank | zscore`；
- 2–5 个成分的 factor ID 与方向；
- `weighting = equal`。

服务端还会冻结每个成分的 label、代码正文与 hash。组合的 `factorCodeSnapshot` 存版本化 JSON 快照，`factorCodeHash` 对整个快照求 hash；因此任何成分代码变化都会生成不同 `variantKey` / `testKey`。单因子旧报告和 V1–V3 spec 不迁移、不重算。

## 计算语义

对每个调仓日：

1. 分别按既有隔离沙箱计算各成分暴露；
2. 只保留所有成分都有有限值的股票；
3. 在该共同截面内逐成分标准化：
   - `rank`：并列值取平均秩，转换为以 0 为中心的 percentile；
   - `zscore`：减均值并除以总体标准差，常数截面记为 0；
4. 应用预先声明的方向后等权平均；
5. 再进入 AnalysisSpec 的暴露异常值和中性化步骤。

先求共同交集再标准化，避免不同成分覆盖范围差异改变分数含义。报告必须展示各成分原始覆盖与最终交集样本量。

## 持久化与 UI

- 新建用户所有的 `FactorComposite` 保存可编辑组合定义；编辑只影响下一次运行，历史报告继续引用冻结快照。
- `FactorReport.factor` 保存 composite ID，报告列表 / URL / Job 恢复继续使用现有契约。
- 因子页增加组合入口与编辑器；相关性矩阵仍是组合前的诊断入口。UI 明示“研究组合，不等于可交易多空策略”。
- 删除组合不删除历史报告，与删除自定义因子后的报告留痕一致。

## 验收

- 纯函数 fixture 验证共同交集、并列 rank、z-score、方向与等权结果。
- 同一组合仅改变任一成分代码，快照 hash 与 report variant 都改变。
- 组合 explore → 冻结报告 → 一次性 holdout → reveal 全链路与单因子同样受约束。
- 前端可创建、编辑、运行、刷新续接并打开历史组合报告；E2E 截图覆盖组合定义与结果。
