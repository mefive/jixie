# 系统功能裁剪计划

日期：2026-10-25。状态：功能范围已收口；Signals 已通过人工 review 与验证，其余裁剪待实施。

目标是把 jixie 收敛为维护者能够独立读懂、审查和修改的个人研究工具。优先删除不再需要的产品能力及其数据、状态和后台流程，再根据剩余需求简化实现。

因子封存与发布合并为“发布版本”一个操作，保留不可变版本和关联分析结果；holdout 整体移除。当前文档记录完整目标范围；实施与验证状态见第 12 节。

## 1 保留的主线

- 股票、ETF 的基础资料、日行情、复权和必要交易规则。
- 股票财报、财务指标和分红研究。
- Research 文档、Markdown 和 Python Cell、运行输出、图表、Agent 辅助编辑。
- Research 数据目录、概念匹配、来源决策、SDK 说明和取数接口。用户已明确撤回删除研究目录的想法；目录内容随实际数据范围缩小。
- 单因子编写与分析、股票和 ETF 策略编写与回测。
- 用户登录、资源归属、帮助文档、中英双语，以及剩余能力需要的沙箱和后台任务。

TypeScript 和 Python 双语言、参数扫描、普通回测条件单、Research Cell 依赖执行等未被点名删除的能力，本轮不自动扩大裁剪范围。

ETF 同步全量基础列表，默认下载规模最大的前 100 只，管理员通过服务器 CLI 维护下载名单。按规模选择，不再人工设置代理资产类别和研究资格；黄金、债券、商品或 QDII ETF 均可进入名单，只保留其自身支持的数据和交易规则。

### 2.1 ETF 全量目录与下载名单

已确定：从 Tushare 同步全量 ETF 基础列表，获取规模数据，默认选取当前上市 ETF 中规模最大的前 100 只下载历史日行情和复权，并继续增量更新。100 是默认数量，管理员可以增减名单。

规模按同一最近可用来源日期的基金资产规模 `totalSize` 排序，不用份额数量 `totalShare` 代替。当前基础目录没有规模字段，需要额外获取全量最新规模快照；不要求先下载所有 ETF 的历史行情。规模缺失的基金不按零值或猜测规模排名，列出缺项，允许管理员按代码加入。

建议默认初始化时生成前 100 名单，日常同步沿用已保存名单；管理员显式执行选取命令时才按最新规模重选，避免自动刷新覆盖人工调整。移出名单停止后续下载，保留已下载历史数据。全量目录仍可搜索，目录和 Agent 明确区分“已收录资料”和“已有行情”。当前规模选出的样本不称为历史各时点的规模前 100。

维护入口是服务器终端 CLI，复用现有命令体系，不新增管理页面或应用管理员角色。拟定命令如下，尚未实现：

| 命令 | 作用 |
| --- | --- |
| `pnpm data etf list` | 查看下载名单、规模日期及数据状态 |
| `pnpm data etf select-top --limit 100` | 更新全量基础列表和最新规模，按规模重建下载名单 |
| `pnpm data etf add 510300.SH` | 按代码添加，后续同步负责回补和增量 |
| `pnpm data etf remove 510300.SH` | 移出下载名单，保留已有数据 |
| `pnpm data sync` | 按保存的下载名单执行统一同步 |

名单仅保存需要下载的代码；不维护首选备选、投资观点、资产代理或研究准入。CLI 的参数与输出、名单持久化和重复添加／移除保持简单、幂等。

### 2.2 结果保存与运行输入

Research 和 Strategy 移除正式证据封存和历史输入回放。因子版本在发布时固定，不因 Signals 删除而一并取消。

保留文档当前输出、策略最近一次结果、必要运行状态与错误；修改代码或参数后，旧输出明确标记需要重跑。因子草稿保留最近分析结果，已发布版本保留关联报告，具体边界见第 7 节。

一次运行仍使用提交时确定的代码和参数，避免后台排队或计算期间读取到另一版编辑内容。这是执行正确性需要的普通输入。Research 和 Strategy 完成后不为证据用途另建永久快照；因子版本的持久化按第 7 节实现。

Research 的图片、表格和图表输出不能因实现目前位于 `evidence/` 就整体删除。按保留的输出展示需求缩小存储和权限读取，移除证据生命周期。

嵌入式 Python 分析继续复用 Research 取数和运行能力，删除成功后永久冻结、输入留存及原输入接续。接续普通文档采用复制当前代码、重新取数和运行的简单行为。

### 2.3 删除来源证据后的数据含义

删除逐字段通用追踪，不自动删除消费者实际需要的公告日期、报告期、可得日期、缺失值及基础数值校验。财报和历史选股仍按当时可得信息计算；无法证明的历史版本继续明确限制，不能将今天的值冒充当时已知值。

财报版本表与通用来源证据不是同一功能。是否进一步简化财报版本存储，需要单独决定，不能在删除 `MarketRecordEvidence` 时顺带改掉财务口径。

### 2.4 指数下载名单与 CLI

已确定：仅维护少量指数，管理员通过服务器 CLI 查看、添加和移除下载名单。保留名单内指数的行情、可获得的历史成分权重和官方估值，继续服务回测基准、历史股票池及独立估值页面。行情、成分和估值的来源支持范围分别判断，不因某一类缺失而伪造其他数据。

删除完整指数目录和天气专用扩展。初始名单建议为沪深 300、中证 500、中证 1000 及回测当前使用的沪深 300 全收益指数；管理员可以调整。指数无需套用 ETF 规模排名。

拟定 `pnpm data index list`、`pnpm data index add 000300.SH`、`pnpm data index remove 000300.SH`，由 `pnpm data sync` 沿用名单同步。移出后保留已有数据；若策略仍使用未同步的基准或成分，明确报告缺口。

## 5 数据维护重新设计

功能裁剪后，维护只负责保留数据的获取、基础校验、幂等写入、增量和历史回补、失败报告。删除业务下游编排，维护完成不再触发信号、账户或因子天气。

建议按剩余数据域保留直接、明确的同步函数，用一个简单入口按顺序调用。仅保存继续同步实际需要的进度；网络失败保留原有数据并给出可重试错误。下载在事务外，替换或追加在短事务内，重复运行不能制造重复数据。

在确定最终数据范围后，重新判断持久分区、公平预算、后台巡检、通用字段证据、全局修订号、失效传播、私有输入副本、比较后发布及 M/P/R 协调各自是否仍必要。只服务已删除功能的机制一并删除；确有剩余读写一致性需求的，选择维护者能讲清楚的最小实现。

最终设计要用一次股票或 ETF 同步说明完整调用链：读进度 → 请求来源 → 校验 → 写库 → 保存进度和摘要。不继续建设可插拔调度平台，也不因删掉所有进度和错误处理而让失败后只能重下全库。

## 6 Agent 代码生成同步裁剪

数据和接口删除必须与 Agent 代码生成在同一改造中完成。目前策略提示词仍指导生成股指期货、行业和龙虎榜代码，因子提示词仍列出资金流和国债收益率字段，嵌入分析仍要求首次成功冻结和输入留存。只停止下载或修改数据库，会让 Agent 按旧能力生成能够通过语法检查、却无法正确计算的代码。

| 入口 | 同步修改内容 |
| --- | --- |
| Factor 编写 Agent | 清理 TS/Python 提示词中的已删除字段、输入声明、研究清单资格、预设和示例；资产类别按最终 ETF 范围保留，不能因为删除底层期货就误删 ETF 价格因子 |
| Strategy 编写 Agent | 清理 TS/Python 提示词、SDK 参考和示例中的期货账户、下单、行业、龙虎榜及资金流能力；因子引用与发布说明按第 7 节同步修改 |
| Research Agent | 保留目录查询和 Python 生成；同步缩小可执行数据绑定、SDK 方法、列名、研究方法说明和模板，不再引导固化、输入回放或已取消的交接流程 |
| 嵌入分析与因子问答 | 更新工具描述、报告上下文和结果读取说明；删除 SQL、Research 冻结、输入留存、holdout 及退役契约的指引，保留因子版本和关联报告说明 |
| 自动交接与其他生成入口 | 删除自动交接和 Curator 的专用生成逻辑；其他保留入口同步修改 SDK 示例、校验和修复反馈 |

所有入口都按保留后的真实 SDK 和数据可得性生成代码。数据不存在或尚未同步时，应说明具体缺口；不能编造字段、补成零、自动替换成其他资产或调用旧 SQL 工具。历史对话中的旧代码不构成当前能力依据。

实施时同步处理五处：模型提示词与工具描述、运行时提供的业务上下文、SDK 契约及生成声明、预设与代码示例、现有编译及元数据／输入校验。优先复用现有契约与校验，不另建 Agent 能力平台。保留概念可以说明来源不可用，但不能继续返回已经删除数据的可执行绑定。

验证同时覆盖保留和删除的能力：用合法 TS/Python 示例验证股票／ETF 因子和策略仍能执行；用期货指令、资金流字段、行业查询、曲线输入及旧 SDK 调用验证不支持项被明确拒绝。检查各 Agent 取得的工具、上下文和目录结果，并做代表性的实际生成与运行验收。普通单元测试使用固定输出，不依赖模型每次生成相同文本；不能只凭删除关键词或编译通过判断取数与计算正确。

主要核对位置：`agent/profiles`、`agent/core.ts`、`agent/tools`、`factor/sandbox/codegen-prompt.ts`、`strategy/sandbox/{typescript,python}/codegen-prompt.ts`、业务 `agent/context.ts`、`research/catalog`、`research/templates`、`research/handoff` 和 `packages/shared/src/sdk`。提示词和工具描述继续使用英文。

## 7 因子版本发布

产品只提供一个“发布版本”操作，发布同时完成固定版本与开放策略引用。不设置独立的封存按钮、封存状态或封存后再发布的步骤，也不包含公开库分享。

### 7.1 最小流程

**编辑草稿 → 分析 → 发布版本。**

继续利用“已发布定义只读、复制产生新草稿”的现有方式，不新增版本平台。草稿允许编辑和分析；发布时固定准确代码、语言、运行时及必要计算定义，并关联同版本成功分析的参数、日期区间和结果。

发布后修改要复制为新草稿，不能覆盖已发布代码或关联报告。发布只要求同版本分析成功，不以收益或显著性阈值作为允许使用的自动判断。

策略只引用明确已发布版本的稳定 key，新版本不自动替换旧引用。这样 `momentum_v1` 和 `momentum_v2` 可以并存；名称仅作展示，不承担版本识别。内置因子升级也遵守同一原则，不能静默覆盖已发布代码。

草稿只保留最近分析结果；已发布版本保留关联报告。这是对通用“只保留最近结果”的因子例外，范围限于版本与结果的对应关系，不恢复 Research 输入回放和整库历史证据。发布固定实现和已得结果，不承诺盈利，也不保证来源修订后的重新运行能逐值一致。

### 7.2 移除 holdout

删除 holdout 的自动窗口、独立提交、父子报告、一次性检验、封存与揭示、日志隐藏及专用准入逻辑。分析由用户选择普通起止日期，日期选择可重复运行；系统不再声明某个区间从未被查看。

发布不再检查 holdout 资格或揭示状态。Agent、SDK、页面、帮助、预设和测试同步删除强制 holdout 指引；普通统计计算保留。旧 holdout 内容不增加兼容运行或揭示链，退役能力直接报错。

## 8 实施顺序与受影响位置

这是同一项完整裁剪工作的依赖顺序，不设只有隐藏页面的阶段性交付。按业务拆成可读的改动单元，避免把全部删除和基础设施重写塞进一份无法审查的 diff。

1. 按已定范围拆分完整业务提交，并按工作流确认每个提交的实施范围；ETF 与指数下载名单按第 2.1 和 2.4 节实施。
2. 删除 Signals、Sharing、天气及其他选定产品能力的入口、Job、工具、状态与跨模块调用。
3. 简化 Research 和 Strategy 的证据与冻结，Factor 按第 7 节处理版本和报告并删除 holdout；接通保留的输出、运行、分析和回测，处理结果读取及嵌入分析。
4. 删除对应 SDK 方法、输入字段、预设、目录条目、数据来源和派生计算；按第 6 节同步修改所有 Agent 生成入口、上下文、示例和校验，更新仍保留的数据目录。
5. 根据最终数据集简化 Maintenance，清除退役机制和消费者。
6. 生成并验证 Prisma 迁移，更新命令、定时服务、镜像与部署影响配置。
7. 同步更新前后端、SDK 文档、中英帮助、测试、`README.md`、`ROADMAP.md`、`CLAUDE.md` 和方法论指导中已不适用的要求。

| 范围 | 主要位置 |
| --- | --- |
| 功能、行情和维护 | `apps/api/src/signals`、`sharing`、`market`、`maintenance`、`factor`、`strategy`、`backtesting` |
| 研究与工具 | `apps/api/src/research/{catalog,datasets,evidence,embedded,handoff,curator}`、`agent/tools/sql`、`agent/profiles` |
| 页面与文案 | `apps/web/src/app-routes.tsx`、各工作台、导航、结果组件、`apps/web/src/i18n`、`apps/docs/src` |
| 契约与运行 | `packages/shared/src`、`apps/sandboxd`、SDK 生成脚本、`apps/api/src/jobs/register.ts`、`bootstrap.ts`、`server.ts` |
| 存储与部署 | `apps/api/prisma/schema.prisma`、Prisma 新迁移、`deploy`、`scripts`、workspace 命令与依赖 |

上述位置是核对入口，不按目录机械整删。例如 `research/evidence` 内的图片输出、`backtesting` 内的现金账户、`infra/email` 内的登录邮件仍可能需要保留。

若改变可部署组件或跨包构建依赖，同步更新 `deploy/component-impact.json` 与 `scripts/deploy/plan-deployment.test.mjs`；Python 镜像输入和 SDK 生成契约同步裁剪。Prisma 迁移由工具生成，不改历史 migration。

## 9 数据迁移与兼容

保留已有文档、因子和策略源码，不迁写旧代码、不保证裁剪后仍可运行。引用被删除接口、字段或数据的代码明确报错即可，不增加兼容转换层。退役功能数据备份后退出产品，不维持旧系统兼容链；不操作开发或生产数据库，相关清理执行另行确认。

已有文档和策略如果引用已删除的 SDK、组合、字段或数据集，应指出具体不支持项，让用户修改代码。禁止静默补零、替换为其他资产或把有缺口的结果显示为成功。

移除用户可见功能时同时移除它的写入口和后台执行，不为旧文档、旧消息和退役页面保留专用运行或结果读取链。旧入口可直接显示停用或不支持。

Research 和 Strategy 删除正式冻结后，旧结果不能与当前编辑代码拼装成看似同一次运行的报告。因子已发布版本及其结果按第 7 节保留对应关系；不支持的旧内容直接报错，不伪造对应关系。

## 10 验收条件

- 删除项在页面、路由、Agent 工具、SDK、Job、CLI、定时服务、同步目录和部署脚本中没有可执行残留。
- 一次数据同步只请求保留的来源和对象；重复执行、部分失败和中断后继续不会破坏已知数据。
- ETF 全量目录和最新规模可同步，默认选规模前 100；管理员 CLI 能查看、重选、添加和移除名单，日常同步不覆盖人工调整。名单内 ETF 能完成回补、增量、Python 取数和现金回测，不依赖旧研究清单。
- 指数仅同步管理员 CLI 名单内的少量对象；行情、成分和估值缺口分别报告，不恢复天气扩展。
- ETF 历史份额研究接口已移除；未来份额变化看板在 ROADMAP 单列，最新规模选池正常工作。
- Research 能编辑和运行 Cell、显示表格与图片、通过保留目录发现数据，不要求固化或输入回放。
- 单因子分析、股票及 ETF 回测、保留的参数扫描可以完成；无期货和被删除来源依赖。
- Agent 不再调用 SQL；仍可发现数据、解释已有输出和通过保留入口开展 Python 分析。
- 各 Agent 的提示词、示例、工具、上下文和校验与裁剪后的 SDK 一致；保留能力能够生成并运行，删除能力给出明确缺口，不生成依赖缺失数据的伪成功代码。
- 修改代码或参数后不会把旧结果误当新结果；当前运行不受之后的编辑影响。
- 已有文档和策略引用退役能力时明确报错，不为旧代码新增兼容实现。
- 因子发布一次完成固定版本和开放引用；已发布代码只读，复制后得到新草稿，新版本不自动替换旧策略引用，报告与版本一致。
- 无 holdout 提交、资格校验、封存揭示、隐藏日志、自动窗口及配套 Agent 指引；普通日期区间分析和因子发布可完成。
- 不再展示行业中性化、宏观风险、跨市场换算等已失去输入的计算选项。
- 在隔离数据库验证存量升级；运行 SDK 生成物检查、类型检查、相关测试、构建和部署计划测试。
- 对改变的主要页面完成浏览器验收并检查截图；测试服务与连接收尾。
- 保留主线能用少量业务函数讲清楚，删除的复杂机制没有以新名字重新出现。
