> [`data-expansion.md`](./data-expansion.md)，因子研究纪律见
> [`factor-research-discipline.md`](./factor-research-discipline.md)，Research 产品边界见
> [`reactive-quant-research-workbench.md`](./reactive-quant-research-workbench.md)。
> 方法论主线参考邹佩轩《穿透财报》《穿透估值》《穿透叙事》三部曲，但本文件记录的是 jixie 的数据、

## 1. 产品决策

jixie 的基本面研究不以继续扩充财务比率和预置因子为主线，而以估值体系组织演绎推理：

```text
财报事实
  → 经营驱动
  → 未来现金流
  → 折现率与终值
  → 正向估值
  → 当前价格隐含假设
  → 叙事兑现与量化验证
```

财报负责回答企业已经发生了什么；估值负责把经营事实和未来假设转成价格含义；叙事是市场价格隐含的
增长、利润率、资本效率、持续时间和风险假设。统计与 FactorReport 用于检验这些观察是否稳定、是否具有
横截面或时序预测力，但不反过来成为基本面体系的第一层结构。

第一版继续遵守“广探索、窄产品化”：先在现有 Research 文档中用透明 Markdown、Python、平台数据和不可变
`ResearchExecution` 完成真实纵向研究，不先建设独立估值页面、目标价卡片或新的隐藏计算引擎。只有公式和
工作流在多个真实案例中反复使用并稳定后，才将其沉淀为公共 SDK helper 或正式产品表面。

## 2. 目标与非目标

### 2.1 目标

1. 保存可审计、可按历史时点读取的三张财务报表及其修订版本；
2. 从原始报表确定性生成单季度、TTM、增长、资本效率和现金流指标；
3. 用经营驱动而不是孤立倍数解释收入、利润、资本投入与自由现金流；
4. 用透明 DCF 完成正向情景估值，并用反向估值提取当前价格隐含的关键假设；
5. 把隐含叙事冻结为有单位、有来源、有日期和反证条件的参数表；
6. 在后续财报发布后比较原假设、实际结果和新隐含假设；
7. 只有经过重复使用的稳定派生指标才进入 Factor 字段目录和正式横截面验证。

### 2.2 非目标

- 不输出平台背书的“合理目标价”或买卖建议；
- 不用单一 DCF 点估值制造虚假精确，必须同时展示场景和敏感性；
- 首版不接券商一致预期、盈利预测、研报、新闻或社交媒体文本；
- 首版不自动让 LLM 生成收入和利润预测；Agent 只能协助解释、写透明代码和核对实际输出；
- 首版不为银行、保险、券商强行套用工业企业 FCFF；
- 不把三张表所有供应商字段直接暴露到 `FactorBar`，也不建设万能财务字段表；
- 不批量生产估值因子或按历史收益自动选择最优估值模型；
- 不在缺少可靠公告版本或可得日时把回填数据标成严格 PIT。

## 3. 第一性原理与研究对象

### 3.1 估值恒等式

非金融企业第一版使用 FCFF 作为主估值语言：

```text
Enterprise Value
  = Σ FCFF_t / (1 + WACC)^t
  + Terminal Value / (1 + WACC)^N

Equity Value
  = Enterprise Value
  + Excess Cash
  + Non-operating Assets
  - Interest-bearing Debt
  - Other Senior Claims

Per-share Value = Equity Value / Diluted Shares
```

终值可以用永续增长或退出倍数表达，但两者只是同一未来假设的不同表达，不得把退出倍数当作没有经营前提的
独立答案。永续增长模型必须满足 `terminalGrowth < WACC`，并披露终值占企业价值比例。

### 3.2 正向估值

正向估值从历史财务事实出发，显式给出未来路径：

- 收入增长由市场空间、价格、销量、份额或其他可观察经营驱动解释；
- 利润率说明规模效应、竞争、成本和会计口径；
- 税后经营利润、再投资和营运资本共同决定 FCFF；
- ROIC 与再投资率约束长期增长，避免增长与资本需求相互矛盾；
- 折现率表达时间价值和风险，不作为事后调整估值以贴近市场价的旋钮；
- 基准、乐观、悲观场景分别冻结假设，不只改变一个笼统增长率。

### 3.3 反向估值与隐含叙事

反向估值固定一组可说明的假设，从当前企业价值反解一个关键未知量，例如：

- 隐含收入 CAGR；
- 隐含稳态利润率；
- 隐含 ROIC 或再投资效率；
- 隐含超额收益持续年限；
- 隐含 WACC 或终值倍数。

首版一次只反解一个主要未知量。多个未知量同时自由求解会产生大量等价答案，只能通过二维敏感性面展示，
不能伪装成市场唯一相信的叙事。

### 3.4 叙事的结构化含义

首版不把叙事定义为新闻摘要或情绪分数，而定义为一组可复查估值假设：

| 字段 | 含义 |
|---|---|
| `assumption` | 收入、利润率、ROIC、再投资率、持续时间、折现率等稳定概念 |
| `value` / `unit` | 明确数值与单位 |
| `startDate` / `horizon` | 假设生效时间与期限 |
| `sourceKind` | 历史事实、用户判断、外部文献、市场反解或计算派生 |
| `sourceRef` | 数据版本、文献或 Research Cell 引用 |
| `rationale` | 为什么使用该假设 |
| `falsification` | 什么实际结果会推翻它 |

这些字段第一版写入 Research Markdown / Python 中的显式表格并由完整执行快照冻结，不新建 `Narrative` 数据表。

## 4. 当前基础与主要缺口

### 4.1 已有能力

- `DailyBasic` 已保存 PE、PE TTM、PB、PS、PS TTM、股息率、总市值和流通市值；
- `FinaIndicator` 已保存 ROE、加权 ROE、ROA、毛利率、净利率、资产负债率、营收/归母净利润同比和
  经营现金流/营业利润；
- `Dividend` 已保存公告、实施状态和除权除息日期；
- Research 已提供单股 `data.equity_fundamentals()`，股票截面/Panel 已提供估值、价格、成交和历史行业；
- Factor 已支持盈利收益率、账面市值比、销售收益率、股息率、规模、ROE、ROE 稳定性和毛利率；
- 股票池、历史指数成分、风险警示、公告日 as-of、复权、行业/规模中性化、Rank IC、分层、成本、
  Newey-West、Fama–MacBeth、Holdout 和不可变报告已经落地。

### 4.2 现有缺口

1. `FinaIndicator` 每个 `tsCode + endDate` 只保留一行，不能完整表达首次公告、调整前、调整后和后续更正；
2. 当前公告日只有日期，没有盘前/盘后时间，公告日当天可用会产生不必要的前视风险；
3. 缺少利润表、资产负债表和现金流量表原始项目，无法可靠计算 FCFF、ROIC、应计利润和净债务；
4. 已落库的增长、净利率和现金流质量字段只在单股 Research 中可读，尚未完整进入横截面/Panel 与 Factor；
5. 缺少累计报告到单季度、TTM、平均资产和跨版本 as-of 的共同计算层；
6. 缺少经营驱动、估值场景、反向估值、敏感性和叙事兑现模板；
7. 当前估值页是指数历史倍数与百分位，不是公司价值研究；两者不应混为一项功能。

## 5. V1 范围

### 5.1 市场与公司范围

- 只做 A 股；港股和美股继续遵循跨市场数据契约，不能复用 A 股字段映射；
- 首个纵向切片只对一般工商业非金融企业开放；银行、保险和券商保存原始来源分类但不进入 FCFF 模板；
- 使用合并报表作为经营与估值主口径，母公司报表可按来源保留但不参与 V1 派生指标；
- 首版使用正式季报、半年报和年报，不接业绩预告、业绩快报和分析师一致预期；
- 研究和回测仍以日频可得时间为边界，不建设财报发布后的分钟级事件交易。

### 5.2 估值范围

- 主模型：非金融企业 FCFF DCF；
- 主输出：企业价值、股权价值、每股价值区间、终值占比、场景表和二维敏感性；
- 主反解：在其余假设冻结时反解一项收入增长、利润率、持续期或折现率；
- DDM、剩余收益、分部加总、实物期权和金融企业专用模型后置；
- 相对估值首版只用于解释和交叉检查，不作为独立第一性原理。

### 5.3 首个真实案例选择门

M0 探针后选择一只满足以下条件的非金融 A 股作为纵向案例：

- 至少连续五年三张表覆盖完整；
- 至少存在一次可辨识的调整前/调整后或更正记录，用于验证版本语义；
- 经营模式能用少量公开驱动解释，不依赖未授权专有数据；
- 股本、复权、估值和行业历史能够对账；
- 不因案例“好算”而预设其投资结论。

另选一只金融股作为负向 fixture，证明 V1 会明确拒绝使用工业企业 FCFF 模板。

## 6. 数据来源与 PIT 契约

### 6.1 来源探针

正式建表前，先用当前账号小样本探测 Tushare：

- `income` / `income_vip`；
- `balancesheet` / `balancesheet_vip`；
- `cashflow` / `cashflow_vip`；
- `fina_indicator` / `fina_indicator_vip`；
- `disclosure_date`；
- `fina_mainbz` 仅作为后续分部/经营驱动候选，不进入 M1 必需范围。

探针必须保存每个接口的当前权限、限频、分页、实际返回字段、空值、重复行、历史深度和修订样本。官方接口
声明三张表包含 `ann_date`、`f_ann_date`、`end_date`、`report_type`、`comp_type` 和 `update_flag`，但是否足以
重建历史发布版本必须以真实返回为准，不能只按字段名称推断。

### 6.2 报告版本身份

来源版本至少由以下语义共同确定：

```text
source
+ tsCode
+ statementKind
+ endDate
+ annDate
+ fAnnDate
+ reportType
+ compType
+ updateFlag
+ sourceRowFingerprint
```

`updateFlag = 1` 只表示供应商当前认为的最新记录，不能覆盖或删除其他版本。同步采用只增不改的来源版本记录；
完全相同的来源行通过稳定指纹幂等去重。

M0 需要验证三张表相同公告是否能可靠组成一个统一 `FinancialReportVersion`。若来源键不能稳定对齐，则三张表
各自保存版本，由 resolver 在读取时组成财务状态，不能为了数据库外观整齐而虚构共同版本。

### 6.3 可得时间

每条来源记录同时保留：

- `annDate`：来源公告日；
- `fAnnDate`：来源实际公告日；
- `observedAt`：平台首次抓到该版本的时间；
- `availableDate`：研究允许使用的首个交易日；
- `availabilityQuality`：`exact`、`conservative` 或 `reconstructed`。

V1 采用保守规则：

1. 优先使用已核验的实际公告日，不能用计划披露日代替；
2. 没有可靠盘前/盘后时间时，`availableDate` 为实际公告日之后的下一交易日；
3. 周末和节假日按证券所属市场交易日历推进；
4. 回填得到的供应商“调整前/调整后”记录，如果缺少更正实际发布日期，只能标记 `reconstructed`；
5. 严格 PIT 研究默认排除无法确定更正可得时间的重构版本，并在覆盖率中披露。

### 6.4 报表选择规则

- 一般工商业 V1 只计算合并报表；
- 同一历史日期选择 `availableDate <= asOfDate` 的最新合格版本；
- 调整前和调整后都保留，resolver 依据当时已知版本选择，不依据今天的 `updateFlag` 回填过去；
- 某张表缺失时保留部分财务状态并返回明确缺失原因，不用 `FinaIndicator` 静默补出看似完整的 DCF；
- `FinaIndicator` 在迁移期继续服务现有 Factor 与策略，直到新口径完成逐字段对账，不原地改写历史报告。

## 7. 数据模型方向

M0 完成来源身份探针前不生成 migration。首选模型方向如下：

### 7.1 来源版本层

- `FinancialReportVersion`：报告期、公告/实际公告、公司类型、报表类型、可得日、质量和来源指纹；
- `FinancialIncomeStatement`：利润表中进入经营、现金流和估值推导的显式类型化字段；
- `FinancialBalanceSheet`：资产、负债、权益、现金、债务、营运资本和投入资本相关字段；
- `FinancialCashFlowStatement`：经营现金流、资本开支、融资和股东分配相关字段。

不采用任意 `metricName + value` 的 EAV 万能表；首批字段经过语义选择后显式建列。未进入契约的供应商字段不因
“以后可能有用”全部落库。三张表若无法稳定共享父版本，则改为各自独立版本表并由 resolver 组合。

### 7.2 派生层

第一版不建立全市场逐日财务快照或万能 `FinancialMetric` 表：

- 单季度、TTM、FCFF、ROIC 等由共享纯函数从版本化报表计算；
- Research 单股和小规模 Panel 先运行时计算；
- 横截面全市场路径使用批量 loader 和报告内缓存；
- 只有真实性能测试证明重复计算不可接受，才设计按报告版本物化的派生缓存；
- 缓存键必须包含来源版本指纹和派生公式版本，不能只按 `tsCode + endDate` 覆盖。

### 7.3 研究产物层

V1 的估值假设、代码、场景和结果保存在现有 `ResearchDocument` 与不可变 `ResearchExecution`，不新增
`ValuationStudy`、`ValuationScenario` 或 `Narrative` 表。若至少三个真实研究反复需要同一结构，且 Research
文档难以比较或追踪，才另行评估稳定领域模型。

## 8. 标准化计算层

### 8.1 报表规范化

共享计算内核至少覆盖：

- 累计年初至今流量转单季度流量；
- 最近四个单季度组成 TTM；
- 资产负债表期初/期末平均分母；
- 同比、滚动同比和多年 CAGR；
- 报告期长度、非标准年结和缺季检测；
- 负值、零分母和会计科目缺失的明确失败原因；
- 来源版本、公式版本和输入字段血缘。

不能把半年报累计值直接当第二季度值，也不能把新会计准则前后的字段变化静默拼接。

### 8.2 第一批经营与估值指标

第一批稳定概念优先于数量：

| 类别 | 第一批概念 |
|---|---|
| 规模与增长 | 营业收入、收入同比、收入 CAGR |
| 盈利能力 | 毛利率、营业利润率、NOPAT Margin、ROA、ROE |
| 资本效率 | 营运资本、投入资本、资本周转率、ROIC |
| 再投资 | 净资本开支、营运资本增加、再投资率 |
| 现金流 | CFO、FCFF、CFO/净利润、应计比率 |
| 资本结构 | 现金、有息负债、净债务、债务/投入资本 |
| 市场桥接 | 市值、企业价值、稀释股本、每股价值 |

所有概念登记单位、流量/存量语义、累计/单季/TTM 变换、行业适用范围、异常处理和 PIT 来源。

### 8.3 经营驱动

V1 的通用驱动链为：

```text
Revenue
  × Operating Margin
  → EBIT
  → NOPAT
  - Reinvestment
  → FCFF

Growth ≈ Reinvestment Rate × Incremental ROIC
```

行业专属的价格、销量、产能、利用率、用户数、ARPU 等不塞进统一财务模型。后续每增加一种行业驱动模板，
必须有独立数据契约、单位、PIT 和真实案例。`fina_mainbz` 只能在验证分部口径、历史稳定性和修订语义后接入。

## 9. 估值研究模板

### 9.1 文档结构

首个模板只包含 Markdown 和 Python Cell：

1. 研究问题、估值日期、标的、价格和反证条件；
2. 数据版本、公告可得日、财报覆盖和缺失说明；
3. 历史收入、利润率、ROIC、再投资和 FCFF；
4. 经营驱动与基准/乐观/悲观假设；
5. FCFF DCF 与企业价值到股权价值桥接；
6. 折现率、终值、终值占比和二维敏感性；
7. 当前价格隐含的单一关键假设；
8. 历史事实、用户假设和市场反解的对照；
9. 主要风险、不可解释部分、结论和下一次复查条件；
10. 干净环境完整执行与显式封存。

### 9.2 场景与参数纪律

- 每个参数区分历史事实、计算派生、用户假设和市场反解；
- 场景改变必须形成新的 `ResearchExecution`，旧结果不可覆盖；
- 默认参数只是教学起点，不作为平台推荐；
- WACC、终值增长和经营预测必须显示来源与敏感性；
- 终值占比过高、预测期内 ROIC/增长不一致或净债务桥接不完整时显示警告；
- 反向估值求解失败或存在多个区间解时明确报不可识别，不返回任意根。

### 9.3 相对估值的位置

PE、PB、PS、EV/EBITDA 作为 DCF 假设的压缩表达和横向交叉检查：

- PE 联结增长、利润质量、资本需求和权益成本；
- PB 联结 ROE、增长和权益成本，金融企业需另行设计；
- PS 联结可持续利润率、资本效率和风险；
- EV/EBITDA 必须补回资本开支、营运资本、税和资本结构差异。

V1 可在模板中展示历史与同业倍数，但不因“低于历史百分位”自动给出低估结论。

## 10. Research、Agent 与 Factor 边界

### 10.1 Research SDK

公开方法名称在实现前由 `packages/shared/src/research-sdk-contract.ts` 冻结。能力至少包括：

- 按单股和公告可得日读取版本化三张表；
- 读取确定性的标准化指标及其输入版本、公式版本和失败原因；
- 对受控股票池和少量指标形成 PIT 横截面/Panel；
- 读取估值日价格、市值、股本、行业和基准利率；
- 对大表设定行数、日期、股票数量和输出预算，禁止逐股 N+1 调用。

Prisma 表不直接成为 Python 公开 schema。数据目录、Monaco/Pyright stub、Runtime 校验和 Agent Catalog 继续
从 Research SDK Contract 生成。

### 10.2 Agent

Agent 可以：

- 查询财务与估值 SDK；
- 提议透明 Markdown / Python Cell；
- 解释实际运行结果、单位、财务桥接和敏感性；
- 指出假设之间不一致、缺失字段或模型不适用。

Agent 不可以：

- 在没有来源时自动填入公司未来增长或折现率；
- 把 LLM 常识写成财务事实；
- 用自然语言覆盖代码计算结果；
- 把单一估值结果表述为买卖建议；
- 在数据质量不足时绕过 PIT 或改用今天的财务值。

### 10.3 Factor

Factor 是估值研究的可选下游，不是 V1 主入口：

- 首批候选优先来自已经审计的稳定派生概念，例如 FCF Yield、EBIT/EV、ROIC、应计比率和资产增长；
- 新财务输入通过版本化字段目录和 Factor V2 loader 暴露，不继续无限扩张旧 `FactorBar`；
- 每个候选仍需经济逻辑、适用行业、异常值规则、中性化、覆盖、换手、成本和一次性 Holdout；
- 估值模型对单个公司的解释力不等于横截面预测力，反向估值结果也不能自动发布为 Factor。

## 12. 测试与验收

### 12.1 数据与 PIT 单元测试

- 相同来源行重复同步幂等；
- 同报告期多版本并存且选择规则只使用当时可得版本；
- 周末公告、交易日公告和缺时间公告都推进到正确下一交易日；
- `reconstructed` 修订不会被严格 PIT 查询静默使用；
- 合并/母公司、一般工商业/金融、累计/单季不会混用；
- 缺字段、零分母、负投入资本和非标准报告期返回明确状态。

### 12.2 财务计算金标准

- Q2/Q3/Q4 累计值正确拆为单季度；
- TTM 恰好使用连续四个合格季度；
- ROIC、再投资、FCFF 和净债务与手工 fixture 对账；
- 资产负债表和现金变动勾稽在定义容差内；
- 公式版本变化使缓存或结果指纹变化。

### 12.3 估值金标准

- 零增长、稳定增长和有限超额收益期有可手算 fixture；
- WACC 上升时估值下降，FCFF 上升时估值上升；
- `terminalGrowth >= WACC` 被拒绝；
- 企业价值到股权价值和每股价值完整对账；
- 反向求解对已知前向价格恢复原参数；
- 无解、多解或弱识别区间明确返回诊断；
- 敏感性矩阵每个单元与独立 DCF 调用一致。

### 12.4 集成与产品验收

- 真库回填覆盖率、重复率、版本率和缺失率报告通过；
- Research SDK、生成 stub、Runtime 和 Catalog 契约一致；
- 真实纵向案例可从数据目录插入代码并完成全文干净运行；
- 上游财报版本或估值假设变化会使下游输出显式 stale；
- 不可变快照能回看全部假设、代码、数据版本、表格和图表；
- 中英文帮助说明估值不是收益承诺，反向估值不是市场唯一叙事。

## 14. 开放决策与停止条件

M0 必须给出以下结论后才能进入 M1：

1. 三张表能否可靠组成统一报告版本，还是必须独立版本化；
2. Tushare 回填能否提供更正的实际发布日期；
3. 首批明确建列的财务科目和历史覆盖；
4. 当前权限是否支持 VIP 按报告期全市场同步；
5. 首个真实案例及其手工对账来源；
6. `FinaIndicator` 是长期摘要表还是验证后逐步降为兼容层。

出现以下任一情况时停止扩大实现并回到设计：

- 无法解释同一报告期多个来源版本的先后关系；
- 原始字段单位或报表口径在时期之间不可比且无法识别；
- 严格 PIT 覆盖不足以支持计划中的真实案例；
- 估值模板必须依赖当前未授权的经营或预测数据才能工作；
- 新 helper 隐藏的假设多于它消除的重复代码；
- 单一案例尚未闭环就开始建设行业模板、独立页面或大规模因子菜单。
