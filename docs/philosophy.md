# jixie 设计哲学:决策外骨骼

> 2026-07-25 与用户对谈后成文,用户确认「理解得非常准确」。本文回答一个所有功能取舍最终都要回溯的问题:
> **这个系统到底是为了什么而存在。** 产品层的具体原则(中性工具、code-first、个人定位)见 `CLAUDE.md`
> 与 `ROADMAP.md`;本文是它们下面的那一层。

## 一句话

jixie 不是一个赚钱工具,是一套**能把自己的资金放心托付进去、并且自己每一行都理解的决策外骨骼**:
机械化消除行为税,测量体系诚实回答 edge 存不存在,人本身退到元层面只做三件事——
**提假设、审证据、写决策日志**。

## 三层目的(由表及里)

### 第一层:预承诺装置——把「未来的自己」从决策链里摘出去

系统名叫「机械交易系」,真正要机械掉的不是下单动作,而是**未来某个深回撤中的自己**:
那个想砍仓、想改参数、想「就这一次手动干预」的自己。情绪的主战场从来不在每笔交易拿不拿得住,
而在回撤中弃系统、亏损后改参数(见 `ROADMAP.md` 主线六)。

所以本系统里那些看似「研究纪律」的设计,本质全是预承诺机制,没有一个是为了「算得更准」,
全都是为了**让人没法对自己撒谎**:

- **代码即唯一真相**(code-first):策略没有可以口头辩解的模糊地带,系统怎么写的就怎么执行;
- **不可变报告台账**(3.6):跑过的实验删不掉、改不了,失败留痕;
- **一次性 holdout 揭示**(3.6a):保留段只能看一次,看完就永久记录在案——没有「再调调参数重看一次」;
- **诚实计数**:试过多少个变体就是多少个,5% 假阳性提示常驻,不许假装只跑过最后那个成功的;
- **系统级决策日志**(使用原则 6):上线/下线/干预必须留一行字——最大亏损往往藏在「就这一次」里。

判断一个新功能是否值得做,第一个问题永远是:**它让「对自己撒谎」变得更难了,还是更容易了?**

### 第二层:测量仪器——诚实回答「我到底有没有 edge」

本系统的成功标准不是「跑赢市场」,而是「给出可信的答案」。这从三个已拍定的设计里可以反推出来:

- 真实对照基线被定义为「**ETF 定投 + 零精力**」,系统长期跑不过它也是平台给出的诚实答案(使用原则 4);
- 小仓上线的目的被定义为「**测量回测与实盘的落差**」,不是赚钱(使用原则 3);
- 「回测好得离谱 = 先找 bug」排在兴奋之前(使用原则 2)。

一个只想赚钱的人不会这样设计系统;这是测量仪器的设计思路。由此推出可信度的绝对优先级:
成本建模宁可悲观(费后视角、滑点上限)、数据层防幸存者偏差(4.7)、PIT 宁缺毋滥
(历史状态缺数据就明确显示「未过滤」,绝不拿今天的状态套历史)。**仪器可以量程小,但不许有系统性偏差。**

哪怕最终答案是「你跑不赢定投,回去定投吧」,系统也算成功——它替用户省掉了未来十年
用真金白银交学费才能买到的同一个答案。

### 第三层:学习载体——把自己训练成「能独立验证任何策略声明的人」

个人做量化的现实定位是**验证者/实现者,不是发现者**(ROADMAP 3.3 方法论)。市面上遍地是别人的
回测截图和因子文献,而这个系统提供的能力是:「在我的市场、我的成本、我的引擎下重算一遍」。
学习清单逐阶段挂到系统具体体现、因子准入要读文献出处、每个功能先理解再动手——借造系统学量化,
这个验证能力本身比任何单个策略都值钱,而且不随因子衰减。

## 对功能取舍的推论

这三层目的解释了本项目大部分「反常」的取舍,也约束未来的取舍:

1. **运转闭环 > 研究更深。** 一个只停在研究阶段的预承诺装置是自相矛盾的:不真正上线、不接受实盘落差
   的测量,所有纪律设计都只是理论。信号线跑通那天,系统才开始履行真正的职责。(这也是
   `roadmaps/` 战略排序的依据。)
2. **自动化的论证是纪律,不是速度。** 未来接自动下单,是为了拿掉回撤中拒绝执行的那只手,
   不是为了快(主线五)。反过来,**元决策永远归人**:AI 或自动化可以执行、可以研究,
   但上线/下线/改参数的裁决权不外包。
3. **可解释性是生存问题,不是品味问题。** 黑箱与执行纪律冲突——回撤中无法回答「系统坏了吗」的东西,
   人一定会在最坏的时刻抛弃它(3.7 对深度学习的排除由此而来)。
4. **凡让撒谎变容易的功能不做。** 无限次重看 holdout、可删除的实验记录、可任意勾选控制变量直到显著的
   UI(p-hacking 界面)、AI 因子农场——无论多常见,都与第一层目的冲突。
5. **工具中性,不预设风格。** 系统约束的是「怎么决策」,不替用户决定「信什么」——趋势、价值、反转
   都要正确且好写;平台只保证你信的东西被诚实检验、被机械执行。

## 一个自检问题

未来任何功能评审,可以只问一句:

> **两年后某次 -25% 回撤的深夜,这个功能是帮那时的用户守住系统,还是帮他找到了背叛系统的借口?**

帮守住的,做;无关的,看性价比;帮背叛的,不做。
