# jixie 设计哲学：个人多市场量化研究实验室

> 2026-07-25 首次成文；2026-08-12 随目标更新重写。本文回答一个所有功能取舍最终都要回溯的问题：
> **这个系统到底是为了什么而存在。** 产品规则见 `CLAUDE.md`，执行规划见 `ROADMAP.md`，知识范围见
> `docs/learning-map.md`。

## 一句话

jixie 是一座**个人多市场量化研究实验室**：借建设真实系统来系统学习量化投资，用数据、代码和可复现
证据研究中国内地、香港、美国的股票、债券与商品；当前优先学习理论、复现研究和构造分析工具，长期再把
经过验证的认识收敛成可以投入实盘的决策外骨骼。

它不是收益承诺，也不是把主观市场判断换成更复杂的图表。最终目标确实是获得持续费后收益和良好的 Sharpe、
Calmar，但系统首先要证明结论可靠、风险可理解、策略可执行；漂亮的样本内指标不能代替这些证据。

## 三层目的

### 第一层：学习系统——把量化知识变成亲手验证过的能力

当前最重要的目标不是尽快交易，而是把自己训练成能够理解、复现、质疑和改进量化研究的人。学习范围可以覆盖
统计推断、时间序列、因子、资产配置、风险模型、市场微观结构和执行，但不能停留在术语与结论层面。

每个重要主题都应尽量走过同一条证据链：

```text
理论与文献 → 明确假设 → 查数据 → 复现计算 → 检查偏差 → 样本外验证 → 形成自己的结论
```

系统为这条链路提供不同强度的载体：

- 中英文公开帮助负责入门、概念解释和真实页面操作，是学习路径的一部分，不是附属文案；
- Agent 对话、只读 SQL、沙盒计算和计算图卡片承担 notebook-like 的快速探索；
- 因子、策略、组合和风险报告承担可重复的正式研究；
- 失败实验、限制和否决结论同样留痕，避免只记住成功案例。

学习主题可以很广，但不能把每次学习都做成永久产品功能。一次探索只有在被反复使用、需要稳定契约或关系到
研究可信度时，才值得进入正式页面、共享类型和数据库模型。

### 第二层：测量仪器——诚实回答结论是否成立

量化的根基不是“有很多数据”，而是知道数据在何时可得、怎样被处理、结论经不经得起反证。系统必须优先保证：

- code-first：计算定义没有口头解释空间，运行的代码与审查的代码一致；
- PIT 与数据截止日：不使用当时未知的信息，不拿今天的成分、状态或修订值改写历史；
- 真实摩擦：费用、滑点、市场冲击、换汇和不同市场交易制度进入验证；
- 研究纪律：不可变报告、研究卡、holdout、诚实计数和稳健统计限制过拟合与 p-hacking；
- 可复现：数据口径、代码快照、参数、资产范围、基准币种和结果能够重新核对；
- 可解释：知道收益来自什么暴露、在哪些市场状态失效、最坏情形是什么。

中国内地、香港和美国的证券身份、交易日历、时区、币种、税费、公司行动与可投资状态不能被揉成一套模糊
默认值。股票、债券和商品也各有不同的收益来源与风险语言。统一平台的意义是统一研究纪律，不是抹平领域差异。

哪怕最终答案是“这个著名因子在目标市场、目标时期和真实成本下不成立”，研究仍然成功。它把一个外部观点
变成了自己能够审查的证据。

### 第三层：决策外骨骼——把验证过的认识变成长期行动

实盘不是取消，而是延后。只有理论理解、数据基础、研究工具和候选策略足够成熟后，系统才进入模拟盘、小仓和
真实执行阶段。届时它要机械化消除的，是未来深回撤中想临时改规则、拒绝执行或事后改写理由的自己。

原有设计仍然成立：

- 策略代码是唯一执行真相；
- 报告和发布不可变，失败实验不能被删成“从未发生”；
- 一次性 holdout 防止反复偷看未来；
- 上线、下线、改参数和人工干预留下决策日志；
- 自动化可以执行和分析，但元决策最终归人。

长期目标不是某次回测得到高 Sharpe 或高 Calmar，而是找到能够跨时期、跨市场状态、费后仍有正期望，且回撤、
尾部风险、容量和执行难度都能被接受的策略组合。Sharpe 与 Calmar 是重要测量结果，不是可以单独优化的答案。

## 对功能取舍的推论

1. **学习价值与可复现性优先。** 新能力首先回答它帮助理解什么理论、验证什么假设，以及结果如何复查。
2. **广探索、窄产品化。** Agent、Python、脚本和临时报告可以灵活探索；正式产品只吸收反复使用的稳定工作流。
3. **数据分析是核心能力。** 数据查询、统计推断、可视化和结果解释不是策略编辑器的附属功能，而是研究实验室的地基。
4. **统一纪律，不伪造统一市场。** 多市场、多资产共享证据标准，但各自的会计、交易、币种和数据时点规则必须显式建模。
5. **实盘验证延后但不遗忘。** 当前不让券商接入和自动下单挤占学习主线；研究结论仍应从一开始考虑真实成本和未来可执行性。
6. **帮助文档与双语是产品本体。** 一个不能让中文和英文使用者理解方法、完成操作并识别限制的研究功能，不算完整。
7. **可解释性是长期生存条件。** 回撤中无法回答“为什么亏、是否仍符合原假设”的系统，最终无法被稳定执行。

## 两个自检问题

当前阶段评审一个新功能，先问：

> **它帮助我理解了什么、验证了什么，产生的证据能否复查？**

进入实盘阶段后，再加问：

> **两年后某次深回撤的夜里，它会帮助我识别系统状态并守住纪律，还是帮我找到背叛系统的借口？**

第一个问题决定现在是否值得建设；第二个问题约束它最终怎样进入真实资金决策。
