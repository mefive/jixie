## 1. M0 做了什么

M0 没有建表，也没有做估值模型。它用真实接口回答三个问题：财报数据能否批量取得、同一报告期为什么会有多行、
以及历史研究从哪一天开始允许使用每个版本。

可重复运行：

```bash
pnpm --filter api probe:fundamentals -- --json
```

## 2. 真实接口结果

固定主样本为五粮液 `000858.SZ`，历史起点参数为 `20100101`，VIP 报告期为 `20231231`。

| 接口 | 当前权限 | 本次返回 | 关键结论 |
|---|---:|---:|---|
| `income` | 有 | 84 | 覆盖至少 2009 年报至 2026 半年报；存在同日供应商后补和独立后续实际公告日 |
| `balancesheet` | 有 | 100 | 单次恰好 100 行，M1 逐股修复必须按公告日期分段 |
| `cashflow` | 有 | 81 | 三表版本数量与更新时间不一致 |
| 三个 VIP 接口 | 有 | 各取 100+100 | `limit/offset` 生效，两个分页边界不同 |
| `fina_indicator` | 有 | 100 | 继续作为兼容和对账层，不作为新口径事实源 |
| `fina_indicator_vip` | 有 | 100+100 | 可按报告期分页回填 |
| `disclosure_date` | 有 | 106 | `modify_date` 是预约日期修正，不是财务数值更正日期 |
| `fina_mainbz` | 有 | 7 | 可作为 M5 分部研究候选，不是 M1 必需输入 |

当前账号对以上十个接口全部调用成功；连同三张表的 `report_type=4/5` 显式查询，共 16 组探针全部通过。
VIP 探针只取两个 100 行页面，证明分页而不下载整个市场。

Tushare 默认只返回 `report_type=1`。另行指定后，三个接口都能返回 `report_type=4` 的后续比较口径；
`report_type=5` 能保留调整前合并报表。本次五粮液分别取得利润表 `4/5` 类型 65/2 行、资产负债表 28/3
行、现金流量表 58/1 行。M1 必须显式同步 `1/4/5`，不能只调用默认参数。

## 3. 两种“更新”必须分开

### 3.1 Tushare 后补字段

美的集团 `000333.SZ` 2022 年利润表同时返回 `update_flag=0/1` 两行：公告日和实际公告日都是
`20230429`，主营数值相同，后一个版本只补了 `EBIT`。现金流量表还补了折旧和供应商自由现金流。

这不是公司更正证据。旧行保留；同日新增内容标记 `reconstructed`，严格 PIT 查询排除。

### 3.2 上市公司正式更正

兴源环境 `300266.SZ` 在巨潮资讯于 `20240103` 发布公告 `1218790667`，明确更正 2016—2022 年报、
2023 半年报和三季报。Tushare 的 2023 半年报和三季报修订行也把 `f_ann_date` 改为 `20240103`，且更正
后的营业成本、营业利润和净利润与公告一致。

这类记录可由巨潮公告 ID、发布时间、PDF 和明确覆盖的报告期佐证；研究可得日为更正公告后的下一交易日。

巨潮公开网页接口无需登录，可以返回公告 ID、时间、标题和 PDF；但它没有公开 API SLA，所以只是可缓存的佐证，
不能成为 Tushare 同步的硬依赖。PDF 未明确确认受影响报告期时，标题和同日匹配只能算候选，不能升级为 `exact`。

## 4. 冻结的数据规则

1. 利润表、资产负债表、现金流量表各自保存版本，不建立虚假的共享来源版本。
2. 每行保存完整来源身份、首次观察时间和稳定 SHA-256 指纹；相同指纹幂等忽略，不同指纹追加。
3. `update_flag` 不决定公司是否更正，也不决定历史可得日。
4. `exact`：有巨潮正式更正公告，而且 PDF 明确覆盖该报告期。
5. `conservative`：使用 Tushare 实际公告日，并推迟到下一交易日。
6. `reconstructed`：同一实际公告日内内容变化，但没有独立公开时间证据；严格 PIT 默认排除。
7. V1 接受 `report_type=1/4/5`、`comp_type=1` 的一般工商业合并累计报表；`4/5` 只按其实际可得日参与
   历史版本选择，不能覆盖原始版本。

首批金额字段单位统一为人民币元，`total_share` 为股；明确建列清单以
`apps/api/src/fundamentals/source-contract.ts` 的 `FINANCIAL_STATEMENT_FIELDS` 为准。

## 5. M1 输入

- 正向案例：五粮液 `000858.SZ`；
- 正式修订案例：兴源环境 `300266.SZ`；
- 金融拒绝案例：平安银行 `000001.SZ`，其 `comp_type=2`，不得进入工业企业 FCFF；
- 三张表独立版本化，VIP 按报告期分页回填，普通接口按公告日期分段修复；
- `FinaIndicator` 保留原消费路径，只承担兼容和逐字段对账。

M0 没有新增数据库表，也没有修改线上同步任务。M1 才会生成 Prisma migration 并接入 maintenance。
